## 1. 这个包是什么

这是 LinuxDesktopPerfect 的**设计基线**：从需求到接口到清单到判据的闭环。它不是参考资料，而是评审、开发、验收、Agent 改文档的共同依据。

**一条判断标准**：代码行为与本包冲突时以本包为准；本包内部冲突时按 [《01-设计总纲与设计基线管理》](01-设计总纲与设计基线管理.md) §2 的权威顺序裁决。

**这个包和常见设计包的两点不同**：

1. **判据也算设计**：每个模块都有「判据注入点」，每条验收判据都落到一个测试门（TG），红读数也是交付物（[《08-判据先行与界面检测设计说明》](08-判据先行与界面检测设计说明.md)）。
2. **界面以结构定义**：7 个样本界面的元素属性表（角色/名称/状态/动作/判据）是界面的第一判据，像素是第二判据（[《界面设计说明》](界面设计说明.md)）。

## 4. 一页读懂

**本包回答六个问题**：

| 问题 | 一页落点 |
|---|---|
| 系统由什么组成、装在哪 | [《02-系统-子系统设计说明》](02-系统-子系统设计说明.md) §1、§11 |
| 每个模块怎么实现、错了怎么办 | [《03-软件设计说明》](03-软件设计说明.md) §3 |
| 两个进程/两层之间怎么说话 | [《04-接口设计说明》](04-接口设计说明.md) §2~§9 |
| 哪些东西是不可改的契约 | [《05-数据与清单设计说明》](05-数据与清单设计说明.md) §5 |
| 界面怎么算成立 | [《界面设计说明》](界面设计说明.md) §0.5、§2~§8 |
| 凭什么说建成了 | [《08-判据先行与界面检测设计说明》](08-判据先行与界面检测设计说明.md) §4 |

**三条铁律**（与 [《概要设计》](../概要设计.md) ADR-014/ADR-015、ADR-012 对应）：

1. **判据先行**：先写失败断言、跑出红读数，再写实现。
2. **结构优先**：界面先比 AT-SPI 树，再比帧。
3. **诚实降级**：不可实现必须返回明确错误码并登记缺陷册编号。

## 5. 自检（改完必跑）

```bash
node 30-design/设计文档包/界面图/build-wireframe.mjs --check   # 结构图与元素属性表同步
node 30-design/checks/check-links.mjs        # 标记 / 链接 / 裸路径 / 裸行号
node 30-design/checks/check-package.mjs      # 必备文件 / 文档头 / REQ→ACC 覆盖
node 30-design/checks/check-design-ids.mjs   # 编号族定义方 / 引用不悬空 / 模块有设计
node 30-design/checks/check-coverage.mjs     # REQ→MOD→ACC→TG→SCR 矩阵 / 12 项专有面
node 30-design/checks/selftest.mjs           # 检查器负向自检
node 30-design/设计文档包/界面图/build-wireframe.mjs --check   # 结构图与表同步
python3 本体/本体校验.py                     # 本体 13 条判据 + 重生成模型页
node 本体/渲染校验.mjs                       # 模型页 14 条断言
```

**通过标准**：五条文档门禁 `rc=0`，且结构图 `--check` 与两条本体校验全 `rc=0`。出现新的 `ERROR` 先修文档，不要改脚本放宽规则。

| 检查器 | 抓什么 |
|---|---|
| [#链接检查器](../checks/check-links.mjs) | 死链、绝对路径、反斜杠、尖括号、裸 `.md` 路径、裸行号 |
| [#文档包检查器](../checks/check-package.mjs) | 必备文档缺失、文档头字段、编号引用悬空、REQ 无 ACC |
| [#编号检查器](../checks/check-design-ids.mjs) | 定义方缺失、模型外编号、引用未定义、模块无设计小节、01 索引不全、SCR 无元素属性表、目录骨架缺失 |
| [#覆盖检查器](../checks/check-coverage.mjs) | 矩阵缺行/重复/错位、TG 或 SCR 空转、12 项专有面缺判据、界面清单重复 |
| [#自检](../checks/selftest.mjs) | 上述三个检查器的负向断言是否真的会红 |

## 6. 给新人或 Agent 的最短路径

1. 读 [《01-设计总纲与设计基线管理》](01-设计总纲与设计基线管理.md) §2~§4（权威顺序 + 编号 + 索引），**不要先读 03**（太长且是细节）。
2. 手上要改哪块，就只读那一块的「一节」：接口看 04，清单看 05，界面看 [《界面设计说明》](界面设计说明.md) 的对应 SCR，判据看 08 对应测试门。
3. 动笔前跑一遍 §5 五条命令，确认基线是绿的；改完再跑一遍，绿了才算改完。
4. 需要新增编号时：先改 [#设计模型](../model/model.json) 与定义方文档，再改引用方，最后跑检查器。
