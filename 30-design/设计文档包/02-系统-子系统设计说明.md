## 0. 本文件回答什么

在[《概要设计》](../概要设计.md)与模块级设计之间，本文件只回答四个问题：

1. **系统怎么切**：8 个子系统各负责什么、用什么语言、产出什么、在进程里占哪一块、V1 是否必须（§1）。
2. **边界在哪**：每个子系统由哪些模块（MOD-xx）组成、明确不做什么、失败时表现为什么（§2~§9）。
3. **怎么接起来**：谁调谁、走哪条契约（P/Invoke / DUCE / D-Bus / 文件）、落到哪些目录、线程怎么分工（§10~§12）。
4. **坏的时候什么样**：故障域与降级矩阵、需求到系统的映射（§13、§14）。

**不回答**：模块内类结构与状态机（→ 03）、字段级契约与错误码（→ 04）、表结构与读数格式（→ 05）。切分依据不是功能名，而是[《概要设计》](../概要设计.md) ADR-003 的三条契约。

## 1. 系统清单（SYS-1~SYS-8）

| 系统 | 职责（一句话） | 语言 | 产物 | 进程内位置 | V1 是否必须 |
|---|---|---|---|---|---|
| SYS-1 wpf-port | 上游派生、托管适配、PBT、applier | C# / MSBuild | 10 个自产托管件 | 应用进程（CoreCLR）；PBT 在构建期独立进程 | 必须 |
| SYS-2 native-shim | Win32/GDI/GDI+/kernel32 子集与消息泵 | C | `libwpfwin32.so` | 应用进程，dlopen 同进程 | 必须 |
| SYS-3 milcore | DUCE 命令流到 Skia 的渲染与窗口呈现 | C#（AOT 导出 C ABI） | `libwpfgfx_linux.so` | 应用进程，dlopen 同进程 | 必须 |
| SYS-4 text-stack | 字体枚举、shaping、行布局、PTS 替代、CFF、IME 桥 | C# + C | `libdwlinux.so` + 托管行布局件 | 应用进程 | 必须 |
| SYS-5 wic-dwrite | WIC 解码与 ICC 色彩转换 | C | `libwpfwic.so` | 应用进程，dlopen 同进程 | 必须 |
| SYS-6 pack | Ref/Runtime pack、targets、解析与安装 | MSBuild | 2 个 NuGet pack | 构建机；运行期以清单形态进入应用输出 | 必须 |
| SYS-7 winforms-compat | WinForms 加载、核心六控件、MSAA 桥 | C# | 兼容层程序集（进 pack） | 应用进程 | 必须（边界见 ADR-011） |
| SYS-8 service-adapters | 打印、媒体、Ink、UIA、IME、DRM 的系统接入 | C# + C | 无独立产物（链接进 pack） | 应用进程 + 系统服务 | 必须（DRM 走 D-001） |

**三条读表要点**：①产物共 5 个 `.so`——4 个自产 + `libSkiaSharp.so`（三方预编译，随应用输出）；②同进程的理由是 WPF 的 native 调用同步、按句柄、跨调用，跨进程要引入代理与句柄映射，等于重写 Win32 语义；③本表无「否」项：可选性用降级路径表达（§13），不摘掉子系统。

## 2. SYS-1 wpf-port
### 2.1 子系统分解

| 模块 | 职责 | 落点 | 状态 |
|---|---|---|---|
| MOD-01 派生生成 | 从上游快照生成派生树，补丁幂等 | `40-build/appliers/`、`40-build/build/` | 待实现 |
| MOD-02 P/Invoke 适配 | 库名映射、resolver、平台分支 | `40-build/wpf-port/` | 待实现 |
| MOD-03 PBT | XAML/BAML 编译（自产 `PresentationBuildTasks`） | `40-build/wpf-port/` | 待实现 |

| MOD-05 补丁测试 | 每个 applier 的回归与读数 | `50-verify/读数/` | 待实现 |
| MOD-06 判据先行脚手架 | 断言模板、桩件与假件、红读数落盘 | `50-verify/probe/`、`50-verify/fake/` | 待实现 |
### 2.2 边界

| 做 | 不做 |
|---|---|
| 接线全部写在 applier 里，派生树可删可重建；改 P/Invoke 目标库名与平台常量 | 不手改 `40-build/upstream/wpf/`（ADR-002、REQ-FN-005）；不改托管 API 语义、不做二进制兼容（ADR-001） |
| 自产 PBT 与官方逐字节对齐，产出同身份自产件 | 不改应用工程文件与 `UseWPF` 之外的属性（ADR-006） |
### 2.3 职责与失败模式

| 模块 | 失败模式 | 检测方式 | 处置 |
|---|---|---|---|
| MOD-01 | applier 非幂等，两次生成 sha 不同 | 删派生树重跑比对 sha（ACC-005、NF-005） | 判红不合入；契约面漂移由 TG-001 兜底（R-007） |
| MOD-02 | 库名解析失败，`DllNotFoundException` | 启动自检解析每个入口 | 启动失败并给明确错误行（SAFE-018） |
| MOD-04 | 清单缺件导致绑定失败 | pack 解包清单 diff（ACC-003） | 构建失败，不静默跳过 |
| MOD-05/06 | 判据后补，断言向实现妥协 | 红读数时间戳早于实现提交（ADR-014、TG-014） | 判红；按 R-013 处置 |
### 2.4 对外契约

| 契约 | 对端 | 形态与对拍 | 编号 |
|---|---|---|---|
| P/Invoke C ABI | SYS-2/3/4/5 | 库名 + 入口 + 结构体布局，`exports.txt` 与断言对拍 | TBL-001、TBL-002、IF-001~IF-006 |
| DUCE 字节流 | SYS-3 | 命令 id + 布局 + 资源表，逐命令对拍 | TBL-003、IF-011~IF-014 |
| pack 清单 | SYS-6 / dotnet SDK | 文件名 + Profile + 版本，解包 diff | TBL-007、IF-021~IF-024 |

|---|---|
| 只做 WPF 与 WinForms 实际调用到的 Win32 子集，按调用点收敛；唯一 Xlib 接触点收敛在单文件（ADR-005） | 不做全量 Win32 兼容层；不把 `XEvent`、`Window` 等 X11 概念泄漏给托管层 |

|---|---|---|---|

| MOD-12 | 事件队列重入导致死锁 | 8 h 长跑 + 事件回放（ACC-010、TG-015） | 判红并输出调用栈，不用「偶发」解释 |

| MOD-14 | `System.Drawing.Common` 非 Windows 必抛 | 异常栈出现该程序集 | 自产 Unix 版或包内替换（R-003） |
| MOD-16/17 | 缺口入口返回 0 形成假成功；布局不一致 | TG-001 对拍 + 调用命中计数 | 显式错误码（SAFE-011）、编译期断言（SAFE-012） |

| 模块 | 职责 | 落点 | 状态 |
|---|---|---|---|

| MOD-23 Skia 后端 | 画刷、几何、变换、效果映射到 `SKCanvas` | 同上 | 待实现 |

| 做 | 不做 |
|---|---|
| 只消费 DUCE，输出像素与资源句柄；CPU 后端用 Skia，GPU 后置 | 不感知 WPF 对象模型（ADR-003）；不自研 D3D 替代（ADR-004），不引入 D3DCompiler/vcruntime |

| 模块 | 失败模式 | 检测方式 | 处置 |
|---|---|---|---|
| MOD-21 | 未实现命令被跳过，画面缺块且无报错 | 覆盖表 118/118（ACC-006） | 判红；未实现命令走显式降级入口（SAFE-006） |
| MOD-21 | 非法命令 id 或截断流导致越界读 | 录制流注入截断/篡改 | 返回错误码并停止解码 |
| MOD-22 | 引用计数错，句柄泄漏或悬垂 | 8 h 句柄曲线（NF-004）、释放后访问断言（SAFE-010） | 判红；泄漏登记已知坑 |
| MOD-24 | 帧提交与事件线程竞态 | 帧非空率 300 帧（ACC-007）、消息泵无死锁 | 判红；渲染提交不得持 UI 线程锁（§12） |
| MOD-25 | 入口缺失导致 `dlsym` 后崩 | TG-001 对拍 | 必须显式导出并返回错误（SAFE-011） |

**K-001 后果**：源码未入库前，本节是**目标结构**而非现状；源码结论属 M0 出口，四小节全部标「待实现」，不写成已有能力。
### 4.4 对外契约

| 契约 | 对端 | 形态与对拍 | 编号 |
|---|---|---|---|
| DUCE 命令流 | SYS-1 | 字节流 + 资源表，布局表逐命令对拍 | TBL-003、IF-011~IF-014 |
| `Mil*` 入口 | SYS-1 | C ABI，18 个入口，`exports.txt` | TBL-001、MOD-25 |

## 12. 进程与线程模型

| 执行体 | 归属 | 不能阻塞谁 | 阻塞后果 |
|---|---|---|---|
| 托管 UI 线程（Dispatcher） | 应用进程 | 不得被渲染提交、D-Bus 回调、GStreamer 回调阻塞 | 界面假死，NF-003 判红 |
| X11 事件线程 | MOD-12 | 不得在事件回调里同步等 UI 线程持有的锁 | 消息泵停止，ACC-009 判红 |
| 渲染提交 | MOD-24 | 不得同步等待 UI 线程的布局结果 | 丢帧与撕裂，ACC-007 判红 |
| GStreamer 回调线程 | MOD-83 | 不得直接触碰 WPF 对象，只能投递到 UI 线程 | 崩溃或状态机错乱 |
| D-Bus 线程（IME、AT-SPI） | MOD-36、MOD-81/63 | 不得在总线回调里同步等 UI 线程 | 死锁，GAP-010 类竞态 |
| 打印线程 | MOD-82 | 不得占用 UI 线程做长任务 | 打印期间界面卡死 |

**四条线程纪律**：①只有托管 UI 线程可以改 WPF 对象与视觉树；②原生回调、D-Bus 回调、GStreamer 回调只投递消息，不直接执行托管逻辑；③渲染提交使用快照式输入（DUCE 流已在 UI 线程生成），不反向查询 UI 状态；④原生层内的同步调用不得等待托管侧再次进原生（禁止重入）。

**SM 引用**：应用会话、窗口、消息泵、IME 组合会话、打印作业、媒体播放、无障碍桥连接、applier 再生八个状态机的转移表在[《03-软件设计说明》](03-软件设计说明.md) §4；本节只约束「哪个执行体推进哪个状态机」。

## 15. 性能与容量设计

> 性能不写「尽量快」：每条目标都有统计量、采样口径、测在哪一屏、读数在哪落。数字来源是[《需求与验收判据文档》](../../20-spec/需求与验收判据文档.md) §5 的 NF 条目，本文只做分配与测量设计，不重新定义指标。

### 15.1 性能目标

| 指标 | 目标 | 测量口径 | 测在哪 | 入口（行内代码） | 判据 |
|---|---|---|---|---|---|
| 冷启动 | ≤ 2 s | 进程创建到首帧可见；10 次测量取中位数，首末各弃一次 | SCR-01 | `50-verify/perf/startup.mjs` | NF-001、TG-015 |
| 常驻内存 | ≤ 300 MB | 空窗稳定 60 s 取 RSS；再开 100 控件稳定 60 s 取第二次，取较大者 | SCR-01、SCR-04 | `50-verify/perf/memory.mjs` | NF-002、TG-015 |
| 帧率 | ≥ 60 fps | 1280×1024 静态场景连续 300 帧，按 p95 帧间隔换算，并同时判帧非空率 | SCR-04 | `50-verify/perf/fps.mjs` | NF-003、TG-015 |
| 长跑稳定 | 8 h 无崩溃、无句柄单调增长 | 每 60 s 采样一次句柄计数与 RSS；句柄线性回归斜率 > 0 且总增量 > 5% 判红 | SCR-01 | `50-verify/perf/soak.mjs` | NF-004、TG-015 |
| 再生可重复 | 两次再生产物 sha 完全相同 | 删派生树 → 重跑 applier → 按 [#pack 文件清单](05-数据与清单设计说明.md) §3.7 逐件取 sha | —（构建侧，无界面） | `50-verify/build/regen-sha.mjs` | NF-005、TG-002 |

**三条读表口径**：①「测在哪」只写样本界面编号，具体场景切换由 `50-verify` 脚本负责；②所有读数必须落 `verdict` 四值（`PASS`/`FAIL`/`SKIP`/`DEGRADED`），性能红读数允许长期存在，但必须登记为 `K-` 已知坑并写明当前值；③性能读数不得用「抽样一次」代替 10 次或 300 帧的统计口径（否则读数不可复算）。

### 15.2 容量模型

| 资源 | 上限假设 | 依据 | 超限行为 |
|---|---|---|---|
| 单窗口视觉节点数 | 5×10⁴ 节点 | 待实测确认（WPF 常用表单量级） | 布局阶段按 `LDP-E-DUCE` 域返回明确错误并停止提交该子树，控制台给节点数与窗口标识；不静默丢帧 |
| DUCE 命令队列深度 | 65536 条 / 帧批次 | 待实测确认（118 条命令 × 多视觉树） | 提交端阻塞而非丢弃；超过 200 ms 未消费则按 `LDP-E-DUCE` 域报错并把该帧标 `FAIL`（ACC-006） |
| 资源句柄表条目 | 262144 条 / 进程 | 待实测确认（位图、画刷、几何、字体面） | 分配失败返回 `E_OUTOFMEMORY`（[《04-接口设计说明》](04-接口设计说明.md) §10），不返回空句柄 |
| 字体回退缓存条目 | 4096 族 / 进程 | fontconfig 枚举规模（待实测） | 按 LRU 淘汰并记命中率；淘汰只影响冷启动耗时，不影响正确性，不报错 |
| X11 像素缓冲 | 单窗口 ≤ 8192×8192 | X11 协议与显存现实（待对拍确认） | 建窗失败给明确错误行（含超限尺寸），不静默降分辨率 |
| 读数目录体积 | 单次门 ≤ 200 MB | 30 条 ACC × 树快照 + 帧（待实测） | 按[《05-数据与清单设计说明》](05-数据与清单设计说明.md) §1.3 的保留策略归档，**不删除历史读数** |

**超限纪律**：上表六条全部要求「明确错误或登记降级」，禁止静默丢帧、静默降分辨率、静默丢命令。凡当前没有具体错误码的，先在缺陷册登记 `D-`/`K-` 编号再实现（ADR-012）。

### 15.3 压测与采样方案

| 采集项 | 采样方式 | 统计量 | 红阈值判定 |
|---|---|---|---|
| 帧率 | 帧计数器法（不靠单帧墙钟差值），每 300 帧一个窗口 | p95 帧间隔、帧非空率 | p95 > 16.7 ms 或非空率 < 100% 即红（ACC-007） |
| 内存 | RSS 每 1 s 采样，取 60 s 窗口最大值 | 窗口最大 RSS | > 300 MB 即红（NF-002） |
| 句柄 | X11 窗口/GC/Pixmap 与内部句柄表计数，每 60 s 采样 | 增量、线性回归斜率 | 斜率 > 0 且总增量 > 5% 即红（NF-004） |

**两种会话的差异**：Xvfb 无头会话没有合成器，DWM 走 `DwmIsCompositionEnabled=false` 分支（ACC-026），帧判据可用，是 CI 的默认会话；真 X11 会话带合成器，帧判据作为基准帧采集会话；远程 X11 会话帧受网络影响，**帧判据豁免、结构判据保留**（R-008）。三种会话都必须把会话类型写进读数的 `env` 字段（[《08-判据先行与界面检测设计说明》](08-判据先行与界面检测设计说明.md) §1.5），否则读数不可比。

## 16. 集成与联调设计

### 16.1 集成顺序

| 阶段 | 集成对象 | 依赖 | 出口判据 | 里程碑 |
|---|---|---|---|---|
| I1 原生与窗口 | MOD-11/12/13/17 + X11 服务器 | `libwpfwin32.so` 可装载；X11 可连 | 开窗五动作 + `exports.txt` 对拍差异 0 | M1（ACC-009/010、TG-004） |
| I2 托管与原生（首帧） | MOD-02/21~25 + `libwpfgfx_linux.so` | pack 可解析；Skia 可装载 | 首帧非空；命令覆盖表 118/118 有落点 | M1（ACC-006/007、TG-003） |
| I3 无障碍桥（与首帧同期起飞） | MOD-81/63/86 + AT-SPI 总线 | I2 的窗口已显示 | SCR-01 树骨架与可聚焦控件行吻合，快照可导出 | M1 结构侧（ACC-027、TG-012）；文本类行随 I4 回归 |
| I4 文本栈 | MOD-31~36 | I2 的帧通路 | 三类样本出字 + 复杂脚本 + IME 四路径 | M2（ACC-013~017、TG-005/006） |
| I5 图像与色彩 | MOD-41/42 | I2 | 五格式像素一致 + ICC 色差在阈值内 | M3（ACC-018/019、TG-007） |
| I6 主题、Ribbon 与 DPI | MOD-04 + 资源件 | I4 的文本度量、I5 的图像解码 | 六主题基准帧 + Ribbon 交互 + 三档 DPI 几何 | M3（ACC-011/020/021、TG-008） |
| I7 媒体、Ink 与打印 | MOD-82/83/84 | I2 的呈现通路、I5 的像素 | 播放/暂停/定位；轨迹点数；作业属性 | M4（ACC-022~024、TG-009/010） |
| I8 pack 与 WinForms | MOD-51/52/53/61/62/63 | I1~I7 的全部产物 | pack 清单 diff 为 0；六控件可用；缺失控件不崩 | M6（ACC-001~005/028、TG-002/013） |

**为什么无障碍桥排在首帧同期，而不是等到最后（ADR-015）**：

1. **成本最低的判据要最早拿到**。首帧一出现就能抓树快照；若等到 M5，前面所有界面结论只能靠帧，出了「结构红/帧绿」或反向分叉时无法归因（R-012）。
2. **依赖最少**。桥只消费 `AutomationPeer` 语义与窗口句柄，不等文本 shaping、不等图像解码，因此可以与前两阶段并行推进，不会返工。
3. **顺序不能反**。像素基线一旦先定，后面发现树缺失只能改判据；先定结构判据，帧判据只是补足结构表达不了的属性（渐变、阴影、合成器效果）。
4. **代价写在明处**：结构判据会先红——文本类 label 的 `name` 要等 I4 才稳定，所以 I3 只判骨架与可聚焦控件行，文本行在 I4 后回归补绿，不把「红」当「通过」。

### 16.2 接口联调矩阵

| 接口组 | 联调对端 | 联调用桩件 | 联调判据 |
|---|---|---|---|
| IF-001~IF-006 | X11 服务器、Skia、fontconfig、系统装载器 | `Fake X11`（Xvfb + 事件注入） | TG-001、TG-004 |
| IF-011~IF-014 | Skia、X11 呈现路径 | `Fake 帧源`（录制 DUCE 流） | TG-003、TG-011 |
| IF-021~IF-024 | dotnet SDK、应用工程 | 无需桩件（pack 本身即替身） | TG-002 |
| IF-031 | ibus / fcitx5（D-Bus） | `Fake ibus` | TG-006 |
| IF-041 | CUPS / IPP | `Fake CUPS` | TG-010 |
| IF-051~IF-053 | AT-SPI（D-Bus） | `Fake AT-SPI` | TG-012 |
| IF-061 | GStreamer 1.20 以上 | 无桩件：以登记的不支持格式做负向联调 | TG-009 |
| IF-071~IF-073 | 判据脚本、缺陷册、读数目录 | `Fake AT-SPI` | TG-012、TG-014 |

**桩件纪律**：桩件与真件共用同一个 IF 契约（[《08-判据先行与界面检测设计说明》](08-判据先行与界面检测设计说明.md) §1.4）；桩件上的偏差必须登记为 `D-` 或 `GAP-`，不允许「桩上绿、真机红」时不归因。

### 16.3 数据映射与对拍

联调期三个契约按固定顺序对拍，前一序不过不进下一序：

| 序 | 对拍对象 | 依据 | 差异判据 | 处置 |
|---|---|---|---|---|
| ① | 出口清单与 ABI 布局 | [#出口清单](05-数据与清单设计说明.md) §3.1、§3.2；IF-006 | `dlsym` 缺一个、`_Static_assert` 过不去 | 停止合入，先改实现或清单（R-007） |
| ② | DUCE 命令布局与覆盖表 | [#DUCE 命令覆盖表](05-数据与清单设计说明.md) §3.3；IF-011 | 命令头字段错位、覆盖表状态未知 | 停止合入；缺口登记 `D-`/`GAP-` |
| ③ | pack 清单与目录布局 | [#pack 文件清单](05-数据与清单设计说明.md) §3.7；IF-021、IF-023 | 清单缺件、版本或 Profile 不符 | 构建失败，不静默跳过（REQ-FN-003） |

**映射纪律**：①只改一侧不算完成——契约变更必须「清单 + 实现 + 读数」三者同改（[《05-数据与清单设计说明》](05-数据与清单设计说明.md) §5）；②每轮联调结束把差异条数写进 TG-001 读数，差异非 0 时该轮结论一律不作数。
