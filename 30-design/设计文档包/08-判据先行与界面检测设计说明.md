## 0. 定位与三条铁律

本项目交付的不是「一个能编译的 WPF」，而是「12 项 Windows 专有面在 Linux 上有落点或显式降级」。这件事无法靠人工目测证明，只能靠**先写下的失败断言**。本文是判据的设计，不是验收的附录。

**三条铁律**：

1. **判据先于实现**（ADR-014）：每个模块的第一份提交是判据断言与红读数，第二份才是实现。没有红读数时间戳的模块视为未开工。
2. **结构先于像素**（ADR-015）：界面是否成立，先看 AT-SPI 树的角色/名称/状态/动作，再看帧。像素只判结构表达不了的属性。
3. **读数必须落盘**（REQ-FN-029）：每条判据一行命令、一份读数、一个时间戳。没有读数的「我试过了」不算结论。

**关于路径写法**：本文引用的 `50-verify/` 脚本与读数目录尚未落地，统一用行内代码给机器路径，落地后再改成 `#名` + 链接（AGENTS §2 硬约束 4：不写未验证的结论）。判据脚本一旦落地，[《引用与名称规范》](../../00-admin/引用与名称规范.md) §1 的 `#` 标记规则对它生效。

## 1. 判据先行怎么落（红绿循环）

### 1.1 五步循环与每步产物

| 步 | 动作 | 产物 | 谁来写 |
|---|---|---|---|
| ① 写断言 | 写死输入、期望、失败判据、超时、读数落点 | 判据脚本 + 期望文件 | 模块作者，动工前 |
| ② 跑出红 | 在未实现/桩件上执行，确认**因该功能缺失而红** | 红读数（`50-verify/读数/`） | 模块作者 |
| ③ 写实现 | 只为实现这条断言而写的最小代码 | 实现提交 | 模块作者 |
| ④ 转绿 | 同一命令、同一期望，`rc=0` | 绿读数 | 模块作者 |
| ⑤ 回归 | 该模块所属测试门全量重跑 | 门读数 | MOD-05 / MOD-06 |

**「因该功能缺失而红」是本项目最容易造假的一步**，必须同时满足：①红读数的失败信息指向具体能力（如「AT-SPI 树里没有 Button 角色」），不是「文件不存在」或「命令拼错」；②红读数在被测实现存在之前产生，时间戳早于实现提交；③红读数入 [#判据读数表](05-数据与清单设计说明.md) §3.9 的落盘目录，不被人为清理。

### 1.2 一条判据的最小结构

判据脚本必须能读出下面七个字段，缺一视为判据不成立：

| 字段 | 内容 | 例 |
|---|---|---|
| `acc` | 对应验收判据编号 | `ACC-027` |
| `tg` | 所属测试门 | `TG-012` |
| `input` | 样本工程 / 场景 / 事件脚本的绝对身份（工程名 + sha） | `samples/WpfFirstWindow@<sha>` |
| `expect` | 可机读期望（元素属性表行、帧 AE 阈值、命令覆盖行） | `TBL-010 SCR-01 R2` |
| `fail` | 失败判据（低于/高于/缺失即红） | `role 不匹配或节点缺失即红` |
| `readout` | 读数落点 | `50-verify/读数/ACC-027/2026-11-02T10-00-00Z-01.json` |
| `degrade` | 允许的降级与豁免条件（没有就是 `none`） | `无 AT-SPI 总线时跳过并标 SKIP，不算 PASS` |

**期望一律外置**：期望值不写在脚本的 `if` 里，写在期望文件里（元素属性表 `TBL-010`、阈值表 `TBL-011`、覆盖表 `TBL-003`）。这样「改期望」是一次显式评审，而不是把断言改成当前行为。

### 1.3 判据分层与责任

```text
第 0 层  契约层：exports.txt / win32_abi.h / DUCE 布局 / FrameworkList 对拍（TG-001）
第 1 层  结构层：AT-SPI 树、窗口树、命令覆盖、pack 清单（TG-002/004/012/013）
第 2 层  像素层：帧非空、AE 阈值、DPI 几何（TG-003/007/008/011）
第 3 层  时序层：消息泵无死锁、打印完成、媒体状态机（TG-004/009/010）
第 4 层  长跑层：60 fps、8 h、句柄无泄漏（TG-015）
```

**越靠前的层越不允许跳过**：第 0 层红时，第 1~4 层的绿读数不作为有效结论。

### 1.4 桩件与假件（Fake 也是一等资产）

| 桩件 | 替代什么 | 判定什么 | 归属于 |
|---|---|---|---|
| `Fake X11`（Xvfb + 事件注入） | 真实 X11 会话与人工操作 | 窗口/消息/DPI 判据可在无桌面 CI 上跑 | MOD-06 |
| `Fake AT-SPI`（D-Bus 假总线） | 真实 at-spi2-registryd | 桥的树结构与事件序列（不依赖桌面） | MOD-06/86 |
| `Fake CUPS`（IPP 假服务端） | 真打印机 | 作业属性与页数，不验证墨盒 | MOD-06/82 |
| `Fake ibus`（D-Bus 假输入法） | 真输入法 | 预编辑/提交/取消三条路径 | MOD-06/36 |
| `Fake 帧源`（录制 DUCE 流） | 真实布局 | 渲染后端可脱开 WPF 单独跑 | MOD-21/23 |
| `Fake 时钟` | 系统时间 | 超时、重试、长跑压缩 | MOD-06 |

**纪律**：桩件必须与真实件共用同一接口（[《04-接口设计说明》](04-接口设计说明.md) 的 `IF-` 契约），否则「桩上绿、真机红」不可归因。桩件的偏差必须登记为降级（`D-`）或缺口（`GAP-`）。六个桩件的启动方式、可配置项与偏差登记见[《09-开工前置与切片计划》](09-开工前置与切片计划.md) §8。

### 1.5 读数落盘格式

读数文件是 JSON，字段固定（表结构见 [#判据读数表](05-数据与清单设计说明.md) §3.9）：

```json
{ "acc": "ACC-027", "tg": "TG-012", "rc": 0, "verdict": "PASS",
  "started": "2026-11-02T10:00:00Z", "duration_ms": 4120,
  "env": { "runner": "xvfb", "x11": "Xvfb-21.1", "atspi": "2.46", "dotnet": "10.0.100" },
  "expect_ref": "TBL-010:SCR-01:R2", "diff": [], "degrade": "none" }
```

`verdict` 只允许 `PASS` / `FAIL` / `SKIP` / `DEGRADED` 四个值。**`SKIP` 不是 `PASS`**：统计时单列，报告里必须写出跳过原因。

### 1.6 禁止事项

- 只在交互界面里手工点一遍就宣布通过（不可复算，Agent 无法复核）。
- 把「没崩」当「实现了」——不崩是第 1 层底线，不是等价性结论。
- 实现写完后再补判据，并把断言改成当前行为（这就是 R-013）。
- 为了让判据变绿而放宽阈值、删断言、扩大 `SKIP` 范围。放宽判据必须走 §5 的变更纪律。

**自检**：`grep -c` 每个门的读数目录，比对该门 ACC 数；无读数目录的 ACC 一律视为「待实现」。

## 2. 测试门（TG-001~TG-015）

每门的写法固定：**判据形式 → 先写什么（红）→ 入口 → 读数 → 关联**。

### 2.1 TG-001 契约对拍门（前置门）

- **判据形式**：四个契约文件与实现逐项对拍，差异条数必须为 0（或每条差异有 `D-`/`GAP-` 编号）。
- **先写什么（红）**：`exports.txt` 的入口清单先在派生树上跑一遍，断言「清单里每个入口都能被 `dlsym` 到，且结构体 `_Static_assert` 全过」。派生树尚未生成时，读数必须是 `FAIL`（缺件），不是 `SKIP`。
- **入口**：`node 50-verify/contract/dump-exports.mjs`、`50-verify/contract/abi-assert`（编译期断言）、`node 50-verify/contract/duce-layout.mjs`、`node 50-verify/contract/pack-manifest.mjs`。
- **读数**：每类一份，差异列为 `diff[]`。
- **关联**：REQ-FN-004/006、ADR-003、MOD-02/17/21/25/51、TBL-001~TBL-003、TBL-007、R-007。

### 2.2 TG-002 构建与 pack 门

- **判据形式**：样本工程仅改 `TargetFramework` 后 `dotnet build -c Release` `rc=0`；构建日志出现自产 pack 解析行；pack 解包清单与 [#pack 文件清单](05-数据与清单设计说明.md) §3.7 逐项 diff 为空；反射打印清单内全部资产的 `FullName` 与清单一致（数量口径见 [#pack 文件清单](05-数据与清单设计说明.md) §3.7，不在本文重数）；删派生树重跑 applier 后产物 sha 相同。
- **先写什么（红）**：先写「清单期望 + 身份期望」两份期望文件，在无 pack 时跑出「解析不到」的红读数。
- **入口**：`node 50-verify/build/build-sample.mjs`、`node 50-verify/build/pack-diff.mjs`、`node 50-verify/build/identity.mjs`、`node 50-verify/build/regen-sha.mjs`、`node 50-verify/external/check-external-winapp.mjs`（ACC-031：外部程序集运行）。
- **读数**：构建日志尾部 + diff 结果 + sha 表。
- **关联**：ACC-001~005、ACC-031（外部程序集运行由 MOD-02 的库名映射/resolver 与 MOD-04 的清单身份承接）、MOD-01/04/51/52/53、SM-008、R-007。

### 2.3 TG-003 渲染门

- **判据形式**：DUCE 命令覆盖表 118/118 有实现或登记降级；`WpfTextDemo` 连续 300 帧非空率 100%；15 个场景帧与基准的 AE 在阈值内。
- **先写什么（红）**：先落覆盖表 118 行（全 `待实现`）与 15 个场景的基准帧身份，跑出「0/118」「帧全空」的红读数。
- **入口**：`node 50-verify/render/duce-coverage.mjs`、`node 50-verify/render/frame-probe.mjs --scr SCR-04 --frames 300`、`node 50-verify/render/ae-compare.mjs --scene <n>`。
- **读数**：覆盖表、帧统计、AE 表（[#基准帧与阈值表](05-数据与清单设计说明.md) §3.11）。
- **关联**：ACC-006~008、MOD-21/22/23/24/25、TBL-003/011、R-001。

### 2.4 TG-004 窗口与输入门

- **判据形式**：开窗/移动/缩放/最小化/关闭五动作各一条读数；消息泵在 8 h 内无死锁；事件回放脚本逐条命中（坐标、按钮、滚轮方向）；125%/150%/200% 三档 DPI 几何符合换算；文本与图像剪贴板双向；XDND 拖入命中。
- **先写什么（红）**：先写事件回放脚本与期望动作序列（五动作 + 键鼠 24 条），在仅有空窗时跑出「动作缺失」的红读数。
- **入口**：`node 50-verify/window/lifecycle.mjs`、`node 50-verify/window/replay.mjs --script <id>`、`node 50-verify/window/dpi.mjs --scale 1.25|1.5|2.0`、`node 50-verify/window/clipboard.mjs`。
- **读数**：动作序列与几何表；死锁时输出调用栈。
- **关联**：ACC-009~012、MOD-11/12/13/24、SM-002/SM-003、SCR-01。

### 2.5 TG-005 文本与字体门

- **判据形式**：CJK/拉丁/符号三类样本可出字且回退链命中登记顺序；复杂脚本字形 id 与步进与基准一致；`FlowDocument`/`RichTextBox` 分页、换行、双向文本不崩；CFF 轮廓非空且与 FreeType 解析一致。
- **先写什么（红）**：先把三类样本的期望字形 id 表与回退链期望落盘，跑出「无字体」「字形 id 全 0」的红读数。
- **入口**：`node 50-verify/text/font-enum.mjs`、`node 50-verify/text/shaping.mjs --script <id>`、`node 50-verify/text/linebreak.mjs`、`node 50-verify/text/cff.mjs`。
- **读数**：字形 id 表、回退链命中表、断行位置表。
- **关联**：ACC-013~016、MOD-31~35、TBL-005、SCR-02、R-005。

### 2.6 TG-006 IME 门

- **判据形式**：预编辑串、提交、取消、候选窗定位四条路径各有读数；无输入法时降级为直接键输入并登记（`D-`）。
- **先写什么（红）**：先用 `Fake ibus` 写四条路径的期望事件序列（含候选窗屏幕坐标），跑出「无预编辑事件」的红读数。
- **入口**：`node 50-verify/ime/compose.mjs --case preedit|commit|cancel|candidate`。
- **读数**：事件序列 + 候选窗坐标（窗口坐标 → X11 屏幕坐标的换算结果）。
- **关联**：ACC-017、MOD-36、SM-004、SCR-02、ADR-008。

### 2.7 TG-007 图像与色彩门

- **判据形式**：png/jpeg/gif/bmp/tiff 五格式解码像素与基准逐通道一致；ICC 嵌入图与 Windows 输出色差在阈值内。
- **先写什么（红）**：先落五格式基准像素的 sha 与 ICC 色差阈值，跑出「解码器未注册」的红读数。
- **入口**：`node 50-verify/image/decode.mjs --format <f>`、`node 50-verify/image/icc.mjs --profile <p>`。
- **读数**：像素 sha、色差 ΔE 分布。
- **关联**：ACC-018~019、MOD-41/42、TBL-006、SCR-03。

### 2.8 TG-008 主题与 Ribbon 门

- **判据形式**：Aero/Aero2/AeroLite/Luna/Royale/Classic 六主题各有基准帧且切换不崩；Ribbon 样本渲染与交互通过。
- **先写什么（红）**：先落六主题的基准帧身份与切换序列，跑出「主题资源缺失」的红读数。
- **入口**：`node 50-verify/theme/six-themes.mjs`、`node 50-verify/theme/ribbon.mjs`。
- **读数**：六主题 AE 表、切换序列日志。
- **关联**：ACC-020~021、MOD-04/51、TBL-011、SCR-04、ADR-010。

### 2.9 TG-009 媒体与 Ink 门

- **判据形式**：常见容器/编码播放、暂停、定位三段读数；不支持格式返回明确错误并带 `D-` 编号；笔/触摸轨迹采集与渲染点序列一致；无设备时降级。
- **先写什么（红）**：先写「不支持格式必须报错」的负向断言 + 轨迹点期望序列，跑出「静默返回空」的红读数（这正是 ADR-012 要防的）。
- **入口**：`node 50-verify/media/playback.mjs --case play|pause|seek`、`node 50-verify/media/unsupported.mjs`、`node 50-verify/ink/trace.mjs`。
- **读数**：状态机状态序列、错误码、轨迹点列。
- **关联**：ACC-022~023、MOD-83/84、SM-006、SCR-06、R-006。

### 2.10 TG-010 打印与流文档门

- **判据形式**：打印到 PDF 与 CUPS 队列各一份作业读数；XPS 文档可渲染；`FlowDocumentReader` 分页/缩放/查找不崩。
- **先写什么（红）**：先用 `Fake CUPS` 写作业属性期望（页数、介质、DPI），跑出「无作业提交」的红读数。
- **入口**：`node 50-verify/print/xps-render.mjs`、`node 50-verify/print/cups-submit.mjs`、`node 50-verify/doc/flowreader.mjs`。
- **读数**：作业属性、页数、渲染帧。
- **关联**：ACC-024~025、MOD-82/33/24、SM-005、SCR-05。

### 2.11 TG-011 合成与 DWM 门

- **判据形式**：有合成器时复用其合成；无合成器时 `DwmIsCompositionEnabled=false` 路径成立且日志明确；远程 Xvfb 会话有读数。
- **先写什么（红）**：先写两种会话（有/无合成器）的期望读数，跑出「两条路径读数相同」的红读数（说明没有真的分支）。
- **入口**：`node 50-verify/compose/dwm-detect.mjs --session composite|plain|remote`。
- **读数**：`DwmIsCompositionEnabled` 读数 + 呈现路径标记。
- **关联**：ACC-026、MOD-11/24、R-008、SCR-01/SCR-04。

### 2.12 TG-012 无障碍门（本文核心）

- **判据形式**：`SCR-01~SCR-07` 的 AT-SPI 树快照与[《界面设计说明》](界面设计说明.md) 元素属性表逐行吻合（角色/名称/状态/动作四列）；8 类控件的动作可被调用并产生登记的可观察效果；事件序列（焦点/值变化/结构变化）按脚本命中。
- **先写什么（红）**：先把 `SCR-01` 的元素属性表落成期望文件（`TBL-010`），在桥未实现时跑出「无障碍总线无此应用」「控件角色全为 `unknown`」的红读数。这条红读数必须在首个窗口能显示之前产生（ADR-015）。
- **入口**：`node 50-verify/a11y/snapshot.mjs --scr SCR-01`、`node 50-verify/a11y/assert-tree.mjs --scr SCR-01`、`node 50-verify/a11y/actions.mjs`、`node 50-verify/a11y/events.mjs`。
- **读数**：树快照 JSON（[IF-071](04-接口设计说明.md) §9.1）+ 逐行 diff + 动作调用结果。
- **关联**：ACC-027、MOD-81/63/86、SM-007、TBL-010/012、SCR-01~SCR-07、R-004/R-012。

### 2.13 TG-013 WinForms 门

- **判据形式**：WinForms 样本加载成功；核心六控件（Button/TextBox/ListBox/ComboBox/Form/Menu）可用；常用控件可用；未实现控件在控制台输出带控件名与 `D-` 编号的错误并渲染空白占位，进程**不退出**；MSAA→AT-SPI 桥通。
- **先写什么（红）**：先写「缺失控件必须报错且不崩溃」的负向断言（用一个刻意不实现的控件），跑出「静默崩溃」的红读数。
- **入口**：`node 50-verify/winforms/load.mjs`、`node 50-verify/winforms/six-controls.mjs`、`node 50-verify/winforms/missing-control.mjs`、`node 50-verify/winforms/msaa-bridge.mjs`。
- **读数**：控件清单命中表、错误行、桥树快照。
- **关联**：ACC-028、MOD-61/62/63、DQ-003、ADR-011、SCR-07、R-010。

### 2.14 TG-014 可复算与降级门

- **判据形式**：`50-verify/` 索引表逐条可执行且落盘；缺陷册每条降级的触发条件/返回码/可见行为/判据四要素齐全；全仓扫描无「未登记的静默失败」。

## 3. 界面检测流水线

### 3.1 三种运行形态

| 形态 | 用途 | 约束 |
|---|---|---|
| Xvfb 无头 | CI 与 Agent 自检；结构判据主战场 | 无合成器，DWM 走 `false` 分支（TG-011 必须用真会话补一轮） |
| 真 X11 桌面 | 人工核对 + 帧基准采集 | 需固定 DPI、固定字体集、固定主题 |
| 远程 X11 | R-008 的降级路径 | 只保证结构判据，帧判据豁免 |

### 3.2 快照采集（IF-071）

快照是界面的机器表示，字段与[《04-接口设计说明》](04-接口设计说明.md) §9.1 一致。关键字段：

| 字段 | 含义 | 用途 |
|---|---|---|
| `path` | 由根到节点的稳定路径（`0/1/2`，按树序） | 结构 diff 的键，不受坐标影响 |
| `role` | AT-SPI 角色（经 `TBL-012` 从 UIA `ControlType` 映射） | 第一判据 |
| `name` | 可访问名称（WPF `AutomationPeer.GetName()`） | 第一判据；空名视为缺陷 |
| `states` | 状态位集合（`enabled`/`focusable`/`focused`/`selected`/`checked`/`expanded`/`editable`…） | 第一判据 |
| `actions` | 可调用动作集合（`click`/`press`/`set-text`/`select`/`expand`…） | 第一判据 |
| `bounds` | 屏幕矩形（像素） | 只用于「结构对但位置错」，不参与结构 diff |
| `value` | 文本值（`TextBox`/`ComboBox`） | 第一判据 |
| `relations` | 关系（`labelled-by`/`controlled-by`/`member-of`） | 第一判据（表单可用性） |

**为什么用 `path` 而不是坐标**：坐标随 DPI、字体、窗口尺寸漂移；树序稳定。结构 diff 只比 `path` + 四列（role/name/states/actions）+ `value`/`relations`，`bounds` 单列比对。

### 3.3 结构断言

对[《界面设计说明》](界面设计说明.md) 每个 SCR 的元素属性表逐行断言：

1. **存在性**：该 `path` 存在，`role` 与期望一致。
2. **命名**：`name` 与期望文案一致（允许登记的正则，如含计数的「已选 n 项」）。
3. **状态**：`states` 包含期望位；`disabled` 之类负向状态也要断言。
4. **动作**：`actions` 覆盖期望集合；调用动作后产生登记的可观察变化（值变、结构变、事件变）。
5. **关系**：表单类控件的 `labelled-by` 必须指向存在的标签节点。

**一条断言一行读数**，不要「一次点完所有控件再报总账」——分叉时无法归因。

### 3.4 帧判据（第二判据）

只在以下情形使用帧：①结构表达了但视觉明显坏（如字形为豆腐块，结构上仍是文本节点）；②结构表达不了的属性（渐变、阴影、圆角、合成器效果）；③回归定位（结构 diff 已指向某个子树，用帧确认视觉后果）。

帧比较统一走 AE 指标 + 阈值（[#基准帧与阈值表](05-数据与清单设计说明.md) §3.11），阈值只允许按 ADR-012 的变更纪律调整。

### 3.5 分叉处理

| 情形 | 含义 | 处置 |
|---|---|---|
| 结构绿 + 帧红 | 树对、画错（典型：字体回退错、DPI 缩放错、合成缺失） | 先查 `TBL-005`/几何，再比帧定位；登记 `K-` 或 `D-` |
| 结构红 + 帧绿 | 桥漏节点或角色映射错（对视觉无害但无障碍不可用） | 按 R-004 修桥与 `TBL-012`；缺角色先登记 `GAP-` |
| 两者皆红 | 功能未实现或整体未接线 | 回到该门红读数，不猜 |
| 两者皆绿但人工觉得不对 | 期望表本身漏了属性 | 补[《界面设计说明》](界面设计说明.md) 元素属性表，再补断言（这是唯一允许「先绿后补」的路径，且补的是期望不是实现） |

### 3.6 检测产物布局

```text

  读数/
    ACC-027/
      2026-11-02T10-00-00Z-01.json      # 单条判据读数
      tree-SCR-01.json                  # 该次快照
  index/索引表.md                        # ACC → 命令 → 读数（人读）
```

索引表是 REQ-FN-029 的直接交付物；索引表每行必须能复制成一条命令直接跑。`读数/ACC-xxx/` 子目录由判据运行时创建，**不入版本控制**（`.gitignore` 已排除，生成物清单见 [#设计模型](../model/model.json) 的 `generatedDirs`）；进版本的是索引表与[#判据读数表](05-数据与清单设计说明.md) §3.9 的结构。

### 3.7 给后续 Agent 用的读取方式

后续自动检测界面时，只用两样东西就能判断「界面是否成立」：

1. **期望**：[《界面设计说明》](界面设计说明.md) 的元素属性表（`TBL-010` 的期望侧），按 `SCR` + `path` 索引。
2. **实测**：`50-verify/读数/ACC-027/tree-<SCR>.json` 的最新快照。

按 `path` join，逐列比较 `role`/`name`/`states`/`actions`/`value`/`relations`，输出「缺失节点 / 角色不符 / 名称不符 / 状态不符 / 动作缺失 / 关系断裂」六类差异。**不需要截图，不需要 OCR，不需要像素阈值**——这是 ADR-015 想要的东西。

## 5. 判据变更纪律

判据比实现严格是常态，所以判据变更要付出比实现变更更高的成本：

1. **收紧判据**：随时允许，只需跑一遍确认当前实现转红（这就是新的红读数）。
2. **放宽判据**（阈值变松、断言变少、`SKIP` 变多）：必须同时给出①放宽理由（为什么原判据不可达：环境/规范/上游限制）；②变更单，记入[《07-质量记录包》](07-质量记录包.md) §5 更改记录；③降级或缺口登记（`D-` / `GAP-`）；④放宽前的红读数与放宽后的读数各一份。
3. **删除判据**：不允许。判据可以降级为「长期红 + 登记 `K-`」，但不得删除——删除会让历史结论失去依据。
4. **期望文件（`TBL-003`/`TBL-010`/`TBL-011`）的任何改动**都按上面三条处理，因为期望就是判据。
