## 0. 范围与原则

### 0.1 为什么用清单而不是数据库

本项目没有数据库，也不需要数据库。需要被「写死并可对拍」的东西只有四类：C 入口清单、结构体布局断言、命令布局与覆盖、pack 文件清单。它们的共同点是**必须以文本形态进版本控制**，否则对拍不可复算。

| 理由 | 说明 | 反面代价 |
|---|---|---|
| 对拍对象是文本 | 契约要与上游声明、实现导出表、pack 解包结果逐项 diff，文本 diff 最直接 | 数据库要写导出器，多一层失真的可能 |
| 进版本控制即可审计 | 每个契约文件的每次变化都能看到 diff，评审与回滚成本最低 | 二进制或库内存储无法评审 |
| 生成与校验分离 | 生成器写文件，校验器读文件，二者不共享内存状态，「生成器说对就算对」不可能发生 | 同进程校验会自证 |
| 运行时才需要结构化 | 句柄表、字体缓存、解码器注册表这类只在进程内存在，用内存表 + 可导出快照 | 落库会引入并发与迁移负担 |

### 0.2 清单即契约

| 规则 | 内容 | 依据 |
|---|---|---|
| 一处定义 | 一个事实只在一个文件里出现；其它文件引用编号或列名，不复制内容 | 编号纪律 |
| 差异即失败 | 契约文件与实现不一致时判红，不做「容忍 N 条差异」的配置 | [《概要设计》](../概要设计.md) §7 三条硬规则 |
| 缺件即失败 | 清单缺件视为构建失败，不静默跳过 | ACC-003 |
| 期望外置 | 判据的期望值来自清单（覆盖表、元素属性表、阈值表），不写在脚本里 | ADR-014 |

### 0.3 四个契约文件是一等资产

`exports.txt`、`win32_abi.h`、DUCE 布局表、`FrameworkList` 与实现同迁、同评审、同版本化；它们不是构建中间产物。

| 契约文件 | 本文的对应表 | 谁生成 | 谁消费 |
|---|---|---|---|
| `exports.txt` | TBL-001 出口清单 | MOD-02/17/25 | MOD-17、TG-001 对拍 |
| `win32_abi.h` | TBL-002 ABI 布局断言表 | MOD-17 | 编译期断言、TG-001 |
| DUCE 布局表 | TBL-003 命令覆盖表 | MOD-21 | MOD-21/22、TG-001、TG-003 |
| `FrameworkList` | TBL-007 pack 文件清单 | MOD-51/52 | dotnet SDK、ACC-003/004 |

## 1. 清单约定

### 1.1 生成、校验、版本

| 项 | 约定 |
|---|---|
| 生成器 | 由模块生成，不由人工逐行编辑；人工只改生成器的输入 |
| 校验器 | [#链接检查器](../checks/check-links.mjs)、[#文档包检查器](../checks/check-package.mjs) 覆盖文档侧；契约侧由 `50-verify/contract/` 的对拍脚本覆盖 |
| 版本载体 | 文件头一行 `# version=<上游版本> since=<日期>`；表内每条另带 `since` 或 `status` |
| 幂等 | 同一输入两次生成结果逐字节相同（NF-005） |

### 1.2 冻结与不可变

| 对象 | 是否可改 | 改法 | 判据 |
|---|---|---|---|
| 上游快照（`40-build/upstream/`） | 不可改 | 换快照 + 重跑 applier | REQ-FN-005 |
| 派生树（`40-build/`） | 可再生成 | 只改 applier，不手改 | ACC-005 |
| 契约清单（TBL-001~003、TBL-007） | 只追加 | 新增行；旧行只改 `status` | TG-001 |
| 读数（TBL-009） | 只追加 | 新文件，不覆盖旧文件 | REQ-FN-029 |
| 缺陷登记（TBL-008） | 只追加 | 新增条目；状态可改，历史不改 | REQ-FN-030 |
| 界面元素属性表（TBL-010） | 受控修改 | 改 `path` 等于改判据，走判据变更纪律 | 08 §5 |

### 1.3 保留策略

| 类别 | 保留 | 清理条件 | 依据 |
|---|---|---|---|
| 契约清单 | 永久 | 不清理 | 契约即证据 |
| 判据读数 | 每个 `ACC` 至少保留首末各一份 | 中间读数可按里程碑归档，不得删除首份红读数与最新绿读数 | ADR-014 |
| 缺陷登记 | 永久 | 不清理（含已修复项） | ADR-012 |
| 运行时表（TBL-004~006） | 随进程 | 进程退出即释放；导出快照按需保留 | NF-004 |
| 基准帧与阈值（TBL-011） | 永久 | 阈值变更走判据变更纪律 | 08 §5 |

## 3. 表定义

每张表给两组内容：**列定义**（有哪些列、什么类型、怎么校验）与**生成/校验/生命周期**（谁写、谁读、何时失效、失败怎么办）。

### 3.1 TBL-001 出口清单 `exports.txt`

| 列序 | 列名 | 类型 | 必填 | 取值 | 校验 |
|---|---|---|---|---|---|
| 1 | `lib` | 字符串 | 是 | `.so` 文件名 | 必须在部署清单内 |
| 2 | `symbol` | 字符串 | 是 | C 入口名（区分大小写） | 与声明面逐字一致 |
| 3 | `status` | 枚举 | 是 | `impl` / `stub` / `gap` | 只允许三值；`gap` 必须有缺陷或缺口编号 |
| 4 | `owner` | 字符串 | 是 | 责任模块 | 必须落在 38 个模块内 |
| 5 | `since` | 字符串 | 是 | 首次登记的上游版本（`10.0.x`） | 与 pack 版本可比 |
| 6 | `note` | 字符串 | 否 | 差异或对拍单号 | 无控制字符 |

**`lib` 列语义（2026-10-30 实读后明确）**：`impl`/`stub` 行＝该符号**当前由**这个 `.so` 提供；`gap` 行＝该符号**若实现将落在**这个 `.so`，不代表已有实现。读表时先看 `status` 再看 `lib`。

**`status` 判定口径（补进契约，避免生成器各判一套）**：`impl`＝C 源里有实现（含带状态机/计数器的错误返回，例如 PTS 的 `WPF_PTS_ERR_NOT_IMPLEMENTED` 路径）；`stub`＝函数体纯常量返回（含直接返回 `ERROR_CALL_NOT_IMPLEMENTED`/`E_NOTIMPL`）；`gap`＝上游有声明但 C 源无实现。

**`libdwlinux.so` 在本清单 0 行**：上游 `DllImport` 面里没有 `dwrite` 库名——DirectWrite 面在 `DirectWriteForwarder` 程序集（pack 内的托管件），它的 Linux 替换属 pack 侧，不经 P/Invoke 清单；映射口径待 TG-001 对拍确认（见 09 §10）。

| 环节 | 责任方 | 触发 | 产物或读数 | 失败处置 |
|---|---|---|---|---|
| 生成 | MOD-02/17/25 | 上游声明面变化、实现增删符号 | 新清单 | 生成器报错即阻断构建 |
| 校验 | `50-verify/contract/` 对拍脚本 | 每次构建 | 差异条数（必须为 0） | 差异即失败（TG-001） |
| 冻结 | 设计基线 | 里程碑出口 | 清单 sha | sha 变化须有变更记录 |
| 退役 | 不允许 | — | — | 只改 `status=gap`，不删行 |

### 3.3 TBL-003 DUCE 命令覆盖表（118 行口径）

**id 不连续（2026-10-30 实读）**：118 条命令的 id 是 `0x00~0x3d` 与 `0x57~0x8e` 两段，缺口 `0x3e~0x56` 共 25 个。判据按「118 条 + 无重复 + 升序 + 缺口登记」，**不要**按「连续 0x00~0x75」判定；`50-verify/fake/duce-replay.mjs --strict-contiguous` 可显式取证。

**两个视角，一张表**：本表同时承载「布局」（参数结构体/字节长度）与「覆盖」（实现状态/降级编号）；`ACC-006` 与读数指针固定在 08 §4 矩阵与读数目录，不在此重列（避免两处定义）。

| 列序 | 列名 | 类型 | 必填 | 取值 | 校验 |
|---|---|---|---|---|---|
| 1 | `id` | 整数 | 是 | 命令 id（两段：`0x00~0x3d`、`0x57~0x8e`） | 118 条内唯一、升序 |
| 2 | `名称` | 字符串 | 是 | 上游命令名（`DUCE-COMMANDS.txt`） | 与上游逐字一致 |
| 3 | `参数结构体` | 字符串 | 否 | 托管侧结构体名 | 空＝未解析，`来源` 标待对拍确认 |
| 4 | `字节长度` | 整数或「变长」 | 否 | 定长命令的字节数 | 空/变长须在 04 §3.1 登记 |
| 5 | `实现状态` | 枚举 | 是 | `待实现` / `impl` / `gap`；**当前 `impl` 的含义是「布局已解析」，不是「渲染已实现」** | 渲染覆盖以 `50-verify/render/duce-coverage.mjs` 的 `impl/total` 读数为准（ACC-006），本列不承担渲染实现语义 |
| 6 | `降级编号` | 字符串 | 否 | `D-xxx` / `GAP-xxx` | 有 `gap` 时必填 |
| 7 | `来源` | 字符串 | 是 | 命令清单/布局源文件；不确定写「待对拍确认」 | 可回查 |

| 环节 | 责任方 | 触发 | 产物或读数 | 失败处置 |
|---|---|---|---|---|
| 生成 | MOD-21 + `50-verify/contract/gen-duce-layout.mjs` | 命令清单或布局源变化 | 118 行表（当前：有结构体 103、有字节长度 112、变长 17、无长度 6） | 行数不等于 118 即失败；`--check` 不一致即红 |

| 冻结 | 设计基线 | 上游命令集变化 | 表 sha | 变化须有变更记录 |

### 3.8 TBL-008 缺陷登记表

唯一事实源是 [《已知坑与降级清单》](../../70-operate/已知坑清单.md)；本节只定义机器侧形状与 join 键 `id`。

| 列序 | 列名 | 类型 | 必填 | 取值 | 校验 |
|---|---|---|---|---|---|

## 5. 一致性约束

四个契约文件之间、契约与派生表之间两两对拍；**差异即失败**，不做「容忍若干条」的配置。差异确属受控变化时，先改契约并留变更记录，再改实现。

| 对拍对 | 规则 | 差异处置 |
|---|---|---|
| `exports.txt` ↔ `win32_abi.h` | 清单中每个符号必须有对应声明与断言，签名宽度一致 | 失败（TG-001） |
| `exports.txt` ↔ DUCE 布局表 | 渲染库那一组入口与布局表的命令通道、资源、呈现入口一一对应 | 失败 |
| DUCE 布局表 ↔ TBL-003 | 每行的参数布局登记键必须指向存在的条目，118 行无空键 | 失败 |
| TBL-003 ↔ TBL-001 | 覆盖表里每个命令族的实现模块必须在出口清单中有对应入口 | 失败 |
| `FrameworkList` ↔ TBL-007 | 逐件相等（名、版本、公钥令牌、分组） | 失败（ACC-003/004） |
| TBL-007 ↔ 反射身份表 | 每个自产件的 `FullName` 与清单逐件相等 | 失败（ACC-004） |
| TBL-010 ↔ 界面元素属性表（七列） | 机器侧列与七列逐列对应；`path` 集合相等 | 失败 |
| TBL-009 ↔ 08 §1.5 读数格式 | 字段集合与枚举值相等 | 失败 |
| TBL-008 ↔ 缺陷册正文 | 编号集合相等；机器侧不得新增正文内容 | 失败 |

| 表 | 写者 | 读者 | 并发规则 | 一致性要求 |
|---|---|---|---|---|
