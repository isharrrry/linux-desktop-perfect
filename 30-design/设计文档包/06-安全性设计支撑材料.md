## 0. 定位与写法

**安全要求在本项目里是「可判据的设计约束」，不是原则口号。** 每条 SAFE 必须能回答四件事，缺一即视为未定义：

| 必须回答 | 反例（不接受） | 落点 |
|---|---|---|
| 要求是什么（可判真假，不写形容词） | 「加强安全意识」「注意安全」 | §2 每条第一列 |
| 落在哪个模块或接口上 | 「全项目都要注意」 | §2 每条第二列（MOD / IF / TBL） |
| 怎么验证（命令、断言、读数） | 「评审时看代码」 | §2 每条第三列；汇总见 §6 |
| 违反了会怎样（后果 + 能否被判据抓住） | 「会有安全风险」 | §2 每条第四列 |

**三条写法纪律**：

1. **只写约束，不写现状**：本文不陈述「已经做到」，只定义「必须这样做，否则判红」。实现状态统一写「待实现」或「待对拍确认」。
2. **安全要求不与功能要求混写**：能拿 REQ-FN 表达的不进本文；本文只保留「即使功能正确也不许这样」的约束，例如未实现入口必须显式报错（SAFE-011）。
3. **降级也要安全**：不可实现路径的处置必须满足[《概要设计》](../概要设计.md) ADR-012 与 SAFE-018/SAFE-019，不允许「因为做不到所以静默」。

| 本文件 | 把 §8 展开成 20 条可验证约束，并给出落点与回指 |

## 1. 威胁模型与信任边界

### 1.1 资产

| 资产 | 为什么值钱 | 落点 |
|---|---|---|
| 上游源码快照与版权头 | 一旦剥离版权头或掺入闭源件，整个仓的许可与可重建性同时失效 | `40-build/upstream/wpf/`、MOD-01 |
| 自产件身份（名称/版本/公钥） | 身份不一致会让绑定失败或让应用加载到非预期实现 | MOD-04、MOD-52、TBL-007 |
| 四个契约文件 | `exports.txt`、`win32_abi.h`、DUCE 布局表、`FrameworkList` 是跨层唯一协议；被改即全栈语义漂移 | MOD-17、TBL-001~TBL-003 |
| 进程内原生堆与句柄表 | 同进程意味着原生越界直接损坏托管运行时，无进程保护兜底 | MOD-21/22、TBL-004 |
| 用户输入内容 | 键盘、IME 预编辑、剪贴板与文件路径会进入快照、日志与打印作业 | MOD-36、MOD-86、SAFE-014/020 |
| 无障碍树 | 它把界面结构与控件文本变成可机读数据，等于界面内容的完整副本 | MOD-81/86、TBL-010 |
| 打印作业与文档 | 作业名、介质、目标队列可能被滥用为文件写入或越权提交 | MOD-82、IF-041 |
| 宿主会话权限 | 应用以当前用户身份访问 X11 与 D-Bus；越权或提权会扩大影响面 | MOD-11、SAFE-017 |
| 判据读数 | 读数是「做没做到」的唯一证据；被污染则全部结论不可复算 | MOD-06、TBL-009 |

### 1.2 攻击面

| 入口 | 协议/形态 | 谁能触达 | 校验归属 |
|---|---|---|---|
| D-Bus（IME） | 会话总线方法/信号 | 同会话任意进程、恶意输入法 | MOD-36 → SAFE-005 |
| D-Bus（AT-SPI） | 会话总线对象/事件 | 同会话任意进程、辅助技术实现 | MOD-81/63 → SAFE-005/016 |
| X11 事件流 | X11 协议、合成事件 | 同显示服务器的其他客户端 | MOD-12 → SAFE-013 |
| DUCE 字节流 | 进程内字节流 | 托管层（含被注入的坏数据） | MOD-21 → SAFE-006 |
| 图像文件 | png/jpeg/gif/bmp/tiff | 应用打开的任意文件 | MOD-41 → SAFE-008 |
| 字体文件 | TTF/OTF/CFF | 应用或系统字体目录 | MOD-31/35 → SAFE-009 |
| 打印参数 | IPP 作业属性 | 应用与打印对话框输入 | MOD-82 → SAFE-007 |
| 媒体文件与插件 | GStreamer 管线 | 应用打开的任意媒体 | MOD-83 → §3 许可项 |
| 剪贴板与 XDND | X11 选择与拖放 | 同会话其他客户端 | MOD-11 → SAFE-013 |
| 构建机与依赖源 | NuGet、系统库 | 供应链上游 | MOD-01/51/52 → SAFE-001~004 |

### 1.3 主要威胁

| 威胁 | 入口 | 后果 | 对应 SAFE |
|---|---|---|---|
| 闭源二进制（含 `_cor3.dll` 一类传输包）被顺手打进产物 | pack 组装、依赖还原 | 许可违规且无法从源码重建 | SAFE-001 |
| applier 生成时剥离或改写上游版权头 | 派生树生成 | MIT 义务违反，来源不可追溯 | SAFE-002 |
| LGPL 组件被静态链接，无法替换 | 链接方式选择 | 传染风险与分发义务扩大 | SAFE-003 |
| SBOM 与 pack 实际内容不一致 | 清单生成 | 审计失效，三方件漏报 | SAFE-004 |
| 恶意输入法发超长/错误类型 D-Bus 消息 | D-Bus IME | 越界读、崩溃或状态错乱 | SAFE-005 |
| 篡改或截断的 DUCE 流 | DUCE 解码 | 堆破坏、越界读 | SAFE-006 |
| 打印作业名或目标路径穿越 | CUPS/IPP | 任意文件写 | SAFE-007 |
| 超大或畸形图像触发内存耗尽 | 图像解码 | 拒绝服务 | SAFE-008 |
| 畸形字体触发解析越界 | 字体枚举与 CFF | 启动即崩 | SAFE-009 |
| 句柄未释放或释放后被访问 | 资源表 | 泄漏、悬垂指针 | SAFE-010 |
| 未实现入口返回 0，上层当成功 | ABI 导出层 | 假成功掩盖缺口 | SAFE-011 |
| 结构体布局与托管侧不一致 | ABI 边界 | 栈错位、随机崩溃 | SAFE-012 |
| 跨 ABI 传空值/已释放句柄 | P/Invoke 边界 | 段错误 | SAFE-013 |
| 无障碍快照或诊断日志把用户输入写进读数文件 | 树快照、诊断开关 | 隐私泄漏且随读数长期留存 | SAFE-014、SAFE-020 |

其余威胁面（AT-SPI 动作被扩展成任意注入、桥暴露到网络、安装或运行期提权、失败被静默吞掉、降级缺四要素登记）分别落在 §2.4 与 §2.5 的 SAFE-015~SAFE-019，不在此表重复。

## 2. 安全性要求（SAFE-001~SAFE-020，每条含：要求、落点模块/接口、验证方式、违反后果）

**五组的划分依据**（按「校验发生在哪一层」切，不按功能切）：

| 组 | 关注点 | 为什么不能并进功能需求 |
|---|---|---|
| §2.1 供应链与许可 | 进入产物的东西从哪来、能不能重建 | 功能全绿也可能装进闭源件，只能靠「来源可核」判 |
| §2.2 输入边界 | 外部字节进进程前的校验 | 功能实现关心正确输入，安全关心畸形输入 |
| §2.3 原生内存与句柄 | 同进程原生的生命周期与 ABI 一致性 | 无进程隔离兜底，错了直接拖垮运行时 |
| §2.4 无障碍与隐私 | 界面数据导出与动作授权 | 无障碍可用 ≠ 数据可外泄 |
| §2.5 故障安全与诚实降级 | 失败怎么表现、怎么登记 | 「没崩」不是结论，降级必须可统计（ADR-012） |

### 2.1 供应链与许可：SAFE-001 无闭源二进制进入产物 / SAFE-002 上游版权头保留 / SAFE-003 LGPL 动态链接与可替换 / SAFE-004 SBOM 完整可复算

| 编号 | 要求 | 落点（MOD / IF / TBL） | 验证方式 | 违反后果 |
|---|---|---|---|---|
| SAFE-001 | 产物内不得出现闭源二进制；闭源件只可作为隔离目录里的对照基准，且不进 pack、不进应用输出 | MOD-51/52、IF-021~IF-024、TBL-007 | pack 解包逐件清单 diff + 来源标注核对；对照目录不进构建图（TG-002） | 许可违规且不可重建；NF-006 判红 |
| SAFE-002 | applier 生成的每个派生文件必须保留上游版权头与许可声明，不得改写或删除 | MOD-01、TBL-009 | 派生树全量扫描版权头；与上游快照逐文件比对头部 | MIT 义务违反，来源不可追溯 |
| SAFE-003 | LGPL 组件（GStreamer 及其插件）只允许动态链接；不得静态链接、不得改写其源码后随产物分发 | MOD-83、IF-061 | 对 `.so` 做链接方式检查；替换系统 GStreamer 后重跑媒体读数 | 分发义务扩大，替换权被剥夺 |
| SAFE-004 | SBOM 必须列出全部三方件（名称、版本、许可、链接方式、是否进产物），且两次生成结果可复算一致 | MOD-52、TBL-007、§3 | SBOM 两次生成 sha 比对；与 pack 文件清单 join 后差异为空 | 审计失效，漏报三方件（NF-006 判红） |

### 2.2 输入边界：SAFE-005 D-Bus 消息长度与类型校验 / SAFE-006 DUCE 解码越界与非法命令 / SAFE-007 打印路径不做任意文件写 / SAFE-008 图像解码尺寸与内存上限 / SAFE-009 字体文件解析容错

| 编号 | 要求 | 落点（MOD / IF / TBL） | 验证方式 | 违反后果 |
|---|---|---|---|---|
| SAFE-005 | 所有 D-Bus 入站消息先校验长度与类型，再进入业务逻辑；超限或类型不符即拒绝并留错误行，不得截断后继续使用 | MOD-36/81、IF-031、IF-051 | Fake ibus 与 Fake AT-SPI 注入超长串、错误签名、缺失字段三类消息，断言拒绝且进程存活 | 越界读、崩溃、状态错乱 |
| SAFE-006 | DUCE 解码对命令 id、载荷长度、资源句柄逐项校验；非法命令或截断流必须返回错误码并停止解码 | MOD-21/22、IF-011~IF-014、TBL-003 | 录制流注入非法 id、截断、长度字段与实长不符三类样本，断言返回码与停止消费 | 堆破坏、越界读 |
| SAFE-007 | 打印路径只允许写入由 CUPS 分配的作业通道与登记的输出目录；不得按用户输入拼接任意路径写文件 | MOD-82、IF-041 | Fake CUPS 提交含路径穿越字符的作业名与目标名，断言被拒并留错误行 | 任意文件写 |
| SAFE-008 | 图像解码必须限制像素总量与单张字节上限，超限即拒绝并给出错误码；不得先分配后失败 | MOD-41、TBL-006 | 构造超限尺寸头与压缩炸弹样本，断言拒绝且常驻内存不增长 | 内存耗尽导致拒绝服务 |
| SAFE-009 | 字体文件解析必须容错：表缺失、偏移越界、CFF 轮廓损坏时跳过该字体并留错误行，不得崩溃 | MOD-31/35、TBL-005 | 注入截断字体、篡改表偏移、空 CFF 三类样本，断言跳过 + 错误行 + 其余字体仍可用 | 启动或渲染崩溃 |

### 2.3 原生内存与句柄：SAFE-010 句柄表生命周期与引用计数 / SAFE-011 未实现入口必须显式报错 / SAFE-012 结构体布局断言（`_Static_assert`） / SAFE-013 ABI 边界空值与句柄校验

| 编号 | 要求 | 落点（MOD / IF / TBL） | 验证方式 | 违反后果 |
|---|---|---|---|---|
| SAFE-010 | 句柄表内每个句柄有明确所有者与引用计数；释放后置无效位，重复释放与释放后访问必须是可检测错误 | MOD-22、TBL-004 | 8 h 长跑句柄曲线（NF-004、TG-015）+ 释放后访问断言 | 泄漏、悬垂指针、长跑崩溃 |
| SAFE-011 | 未实现入口必须显式导出并返回明确错误码（`E_NOTIMPL` 一类），或从 `exports.txt` 列为缺口；不得返回 0 伪装成功 | MOD-16/17/25/85、TBL-001 | 逐个入口调用并断言错误码；TG-001 对拍导出清单与实现 | 假成功掩盖缺口，上层逻辑错乱 |
| SAFE-012 | 所有跨 ABI 结构体在编译期以 `_Static_assert` 固定尺寸、对齐与关键字段偏移；不满足即编译失败 | MOD-17、TBL-002 | 编译期断言全过；布局表与实现 diff 为空（TG-001） | 栈错位、随机崩溃且不可复现 |
| SAFE-013 | 每个 ABI 入口先校验空值、句柄有效性与对象类型，再解引用；失败返回错误码而不是崩溃 | MOD-11/12/13/22、IF-001~IF-006 | 传 NULL、已释放句柄、错误类型句柄三类负向用例 | 段错误、进程被拖垮 |

### 2.4 无障碍与隐私：SAFE-014 树快照脱敏（不默认导出密码框内容） / SAFE-015 动作白名单 / SAFE-016 无障碍桥不监听网络

| 编号 | 要求 | 落点（MOD / IF / TBL） | 验证方式 | 违反后果 |
|---|---|---|---|---|
| SAFE-014 | 树快照默认不导出敏感输入内容：口令类控件只写掩码或省略 `value`；脱敏不可由应用侧关闭 | MOD-86、IF-071、TBL-010 | 含口令框的样本快照扫描：断言无明文；开关关闭与打开两种配置都测 | 口令进入读数文件并长期留存 |
| SAFE-015 | 无障碍动作只接受登记白名单（`click`/`press`/`set-text`/`select`/`expand`/`focus`/`scroll`）；未登记动作拒绝并记录，不得退化为任意事件注入 | MOD-81/63/86、IF-053、TBL-012 | 注入未登记动作与越权参数，断言拒绝 + 记录；白名单表与代码枚举 diff 为空 | 越权操作应用与桌面 |
| SAFE-016 | 无障碍桥只连接本机会话总线，不监听网络套接字、不实现远程传输 | MOD-81/63、IF-051~IF-053 | 运行时开放端口检查 + 依赖静态检查 + 桥启动日志的总线地址断言 | 远程读取界面内容 |

### 2.5 故障安全与诚实降级：SAFE-017 运行时不提权 / SAFE-018 失败必须显式退出码与错误行 / SAFE-019 降级四要素齐全 / SAFE-020 诊断开关默认关闭且不记录用户输入内容

| 编号 | 要求 | 落点（MOD / IF / TBL） | 验证方式 | 违反后果 |
|---|---|---|---|---|
| SAFE-017 | 安装到用户目录；运行期不得请求提权、不得调用 `sudo`/polkit 提权接口；需要系统级安装时由显式系统包完成 | MOD-51/52/53、安装脚本 | 以非 root 用户跑全量样本；启动过程断言无提权调用 | 全机影响面扩大，越权写入系统路径 |
| SAFE-018 | 任何失败路径必须有非 0 退出码与一行可定位的错误行（模块 + 原因 + 编号）；禁止静默返回空或假成功 | MOD-06 + 全部、TBL-008 | TG-014 的静默失败扫描；逐条负向用例断言 rc 与错误行格式 | 降级不可见，判据失效（违反 ADR-012） |
| SAFE-019 | 每条降级必须四要素齐全：触发条件、返回码、用户可见行为、缺陷册编号；缺一项即视为未登记降级 | MOD-06/16/85、TBL-008 | TG-014 缺陷册四要素核对；扫描代码中降级分支是否都带编号 | 无法统计降级与失败，验收结论不可信 |
| SAFE-020 | 诊断开关默认关闭；开启后也不得记录用户输入内容（键入、IME 预编辑、剪贴板、文档正文），只记录结构事件与标识 | MOD-06/36/86 | 默认构建下日志扫描无输入文本；开关打开后仍做同样扫描 | 隐私泄漏并被读数文件长期保留 |

**四条读表说明**：①「落点」列必须同时给出模块与契约（IF/TBL）之一，只有模块没有契约视为落点不完整；②「验证方式」列必须能在 `50-verify/` 找到对应入口，本表只给判据形态，命令与阈值在[《08-判据先行与界面检测设计说明》](08-判据先行与界面检测设计说明.md)；③四列中任何一列写「评审确认」「视情况」即视为未定义；④20 条当前状态全部为「待实现」，无一条有实测读数。

## 3. 许可与三方件合规

| 组件 | 许可 | 链接方式 | 是否进产物 | 出处与口径 |
|---|---|---|---|---|

## 4. 无障碍与隐私约束

**核心口径：树快照是「数据」，不是「日志」。** 日志可以粗、可以丢；数据有结构、有留存、有脱敏义务。

| 约束 | 内容 | 落点 |
|---|---|---|
| 定位 | 快照是结构判据的输入数据，随判据读数落盘，不是运行期日志 | MOD-86、IF-071、TBL-010 |
| 默认脱敏 | 口令类控件的 `value` 默认掩码或省略；文本值只在判据需要且已登记时导出 | SAFE-014 |
| 开关归属 | 脱敏由判据侧控制，应用侧不得关闭；开关状态写进读数文件的 `env` | SAFE-014、TBL-009 |
| 内容范围 | 只含被测样本窗口的子树，不采集桌面其他窗口内容 | IF-071 |
| 留存 | 快照与对应读数同期保留；删除策略待裁决，未裁决前不得自动清理 | TBL-009 |
| 共享 | 快照进入交付件前必须过脱敏检查；含输入内容的快照不得出仓 | SAFE-014、SAFE-020 |
| 与日志的分界 | 运行日志只记结构事件与标识，不记控件文本值 | SAFE-020 |
| 快照与像素 | 帧与像素文件随读数保存，但不得包含桌面其他窗口内容（只截被测窗口矩形） | IF-071、TBL-011 |

## 5. 单位与量纲一致性

**为什么单独一节**：安全与判据的争吵常常源于量纲错位——「阈值 2」是 2 像素、2 DIP、还是 2 ΔE？本节把每个量的单位与换算落点钉死，避免同一读数被两种单位解释。

| 量 | 单位 | 换算或口径 | 落点 |
|---|---|---|---|
| 逻辑像素（DIP） | DIP | 96 dpi 下 1 DIP = 1 像素；其余 dpi 下乘以缩放系数 | MOD-13/24 |
| DPI 缩放 | 倍率或 dpi 值 | `scale = dpi / 96`；档位 125%/150%/200%，判定按实际 dpi 记录 | MOD-13/24、ACC-011 |
| 字体尺寸 | pt | `px = pt × dpi / 72`；报告须同时给 pt 与 px | MOD-31/33 |
| 字形步进 | 字体设计单位 | 除以 `unitsPerEm` 后再乘字号，读数统一换算为 DIP | MOD-32/35 |
| 帧时长 | ms | 60 fps 对应 16.667 ms；统计用 300 帧的均值与 p95 | MOD-24、TG-015 |
| AE（绝对误差） | 0~255 通道差 | 两帧逐通道绝对差；求和还是取均值由 TBL-011 固定，报告必须写明口径 | MOD-24、TG-003 |
| ΔE（色差） | 无量纲（CIELAB 空间） | 判据固定用 ΔE00；ΔE76 与 ΔE00 不可混比，报告须写明用的是哪一种 | MOD-42、TG-007 |
| 内存占用 | MiB | 常驻集（RSS）；判据阈值 300 MB 按 MiB 解释 | NF-002、TG-015 |
| 句柄计数 | 个 | 同一采样间隔下的进程句柄总数，须单调性判断 | TG-015 |
| 时间戳 | ISO 8601 UTC | 读数 `started` 与文件名字段同源，不带本地时区 | TBL-009 |

**AE 与 ΔE 的区别（最容易混的一处）**：AE 是**同一坐标系下的像素差**，用于帧与基准帧比对（TG-003）；ΔE 是**不同色彩空间之间的感知色差**，用于 ICC 转换正确性（TG-007）。两者不可互换：把 AE 当 ΔE 会漏掉色彩管理错误，把 ΔE 当 AE 会让帧比对阈值失去意义。

## 8. 人机界面安全性设计

**为什么本项目有人机界面**：本项目的界面不是自己画的产品界面，而是 7 个样本界面（`SCR-01~SCR-07`，见[《界面设计说明》](界面设计说明.md) §1）——它们是验收现场。界面在这里是**证据显示器**：只要能出现「看起来成功、实际没成功」的显示，界面本身就成了安全问题（与 SAFE-018/SAFE-019 同源：假成功即不安全）。因此本节的约束对象是「界面显示什么」与「界面能做什么」，不是视觉风格。

### 8.1 显示界面安全属性

| 属性 | 要求（可判真假） | 落点 |
|---|---|---|
| 错误可见性 | 每条失败路径必须在界面上有可见落点（错误行或状态文本），不得只写日志 | 元素属性表的「名称期望」列；SAFE-018 |
| 降级可见性 | 进入降级时必须显示缺陷册编号（如 `D-001`），未实现控件占位必须显示 `D-` 编号 | GAP-009、D-001；SAFE-019 |
| 状态一致性 | 界面状态读数必须来自同一状态机（`SM-005` 打印、`SM-006` 媒体），不得另算一套 | 03 §4.3.5、§4.3.6；元素属性表的读数行 |
| 禁止假成功 | 界面不得先显示成功再报错；读数 `verdict` 只允许 `PASS`/`FAIL`/`SKIP`/`DEGRADED`，`SKIP` 不得显示为通过 | 08 §1.5、08 §2；SAFE-018 |
| 只读/可写提示 | 只读与禁用必须能从结构判据读出（`!editable`、`!enabled`、`!sensitive`），不靠灰色像素暗示 | 元素属性表「状态期望」列；SAFE-014 的脱敏口径 |
| 误操作保护 | 不可逆动作（打印提交、播放定位、关闭会话）必须有二次确认或可撤销路径；禁用态控件被点击不得产生任何效果 | 界面 §2~§8 交互闭环；SAFE-015 |

**两条界面级强制**：

- **GAP-009**：WinForms 缺失控件的空白占位必须映射为 `filler` 角色且 `name` 含 `D-` 编号——「什么都不显示」等于静默失败，违反 SAFE-019。
- **D-001**：DRM 路径必须让用户看到明确错误，不得静默返回空结果；界面上「没反应」不是降级，是缺陷。

### 8.2 人机接口安全属性

| 属性 | 要求 | 落点 |
|---|---|---|
| 动作白名单 | 界面可触发的动作必须与登记白名单一致（`click`/`press`/`set-text`/`select`/`expand`/`focus`/`scroll`），未登记动作拒绝 | SAFE-015；[《04-接口设计说明》](04-接口设计说明.md) §7.3 |
| 输入校验 | 输入长度与类型在进入业务逻辑前校验；超限拒绝并留错误行，不截断后继续 | SAFE-005；SAFE-007（打印路径） |
| 禁用态不可绕过 | 焦点、Tab 键、快捷键、无障碍动作四条路径对同一控件的禁用态判定必须一致，不得用键盘绕过 | SAFE-015；TG-004 事件回放 |
| 敏感输入不外泄 | 口令类输入在快照与日志中掩码；剪贴板内容不进入读数 | SAFE-014；SAFE-020 |
| 诊断开关默认关闭 | 界面不提供开启诊断的默认入口；开启后只记结构事件，不记输入文本 | SAFE-020；[《05-数据与清单设计说明》](05-数据与清单设计说明.md) §3.9 |

**判据落点**：本节全部条目由 TG-012（无障碍门）与 TG-004（窗口与输入门）承接，红先写什么见[《08-判据先行与界面检测设计说明》](08-判据先行与界面检测设计说明.md) §2.12、§2.4。

| 4 | 未实现入口必须显式失败 | 显式导出并返回 `E_NOTIMPL` 一类错误码，或列入 `exports.txt` 缺口 | SAFE-011；TG-001 |
| 5 | 句柄引用计数成对 | 同一作用域成对 acquire/release；释放置无效位；重复释放可检测 | SAFE-010；TG-015 |
| 6 | 异常不跨 ABI 边界 | C 侧不抛异常；托管侧不得让异常穿过 P/Invoke 边界 | SAFE-013；TG-001 |
| 7 | 入站消息先校验再使用 | D-Bus 与 DUCE 输入先校验长度/签名/命令 id，再进业务 | SAFE-005、SAFE-006；TG-006、TG-003 |
| 8 | 降级必须带编号 | 每个降级分支打印或登记 `D-` 编号，并在缺陷册四要素齐全 | SAFE-019；TG-014 |
| 9 | 产物只含可重建内容 | 禁止闭源二进制进入 pack 与应用输出；SBOM 每件可追 | SAFE-001、SAFE-004；TG-002 |
| 10 | 失败必须可定位 | 非 0 退出码 + 一行错误行（模块 + 原因 + 编号），禁止静默返回空 | SAFE-018；TG-014 |

### 9.2 推荐类（评审关注，允许有理由的例外并登记）

| # | 条款 | 做法 | 检查方式 |
|---|---|---|---|
| 1 | `DllImport` 目标名集中登记 | 库名与入口名集中在 resolver 表，禁止在调用点散写 | TG-001 对拍 `exports.txt` |
| 2 | 错误码按域分配 | 每模块只用自己域内的 `LDP-E-<域>-<序号>`，不跨域复用 | 03 §2.1；代码扫描 |
| 3 | 解码前先按头部预估上限 | 先用尺寸字段判上限，超限即拒绝，避免「先分配后失败」 | SAFE-008；TG-007 |
| 4 | 固定宽度整型与显式填充 | 跨边界结构体不用平台相关宽度类型，避免 ABI 漂移 | SAFE-012；TG-001 |
| 5 | 读数与日志原子写 | 临时文件 + 改名，避免半截文件被当作有效读数 | [《05-数据与清单设计说明》](05-数据与清单设计说明.md) §3.9；TG-014 |
| 6 | 原生回调只投递不执行 | 原生回调只把消息投到 UI 线程，不直接执行托管逻辑 | 02 §12 线程纪律；TG-004 |

### 9.3 禁止类（出现即缺陷，不接受「临时代码」理由）

| # | 禁止 | 为什么 | 检查方式 |
|---|---|---|---|
| 1 | 空捕获 `catch {}` / 空 `except` | 等价于静默吞错，直接违反 SAFE-018 | TG-014 静默失败扫描 |
| 2 | 在 `finally`/析构里吞异常掩盖失败 | 让失败在调用方不可见 | TG-014；SAFE-018 |
| 3 | 用 `assert` 代替运行时错误返回 | release 构建下 `assert` 消失，错误变成未定义行为 | SAFE-011；代码扫描 |
| 4 | 把用户输入拼进文件路径或命令行 | 打印路径与文档路径的穿越风险（SAFE-007） | TG-010 负向用例 |
| 5 | 在日志/读数/快照里记用户输入明文 | 口令与正文长期留存（SAFE-014/020） | TG-012 快照明文扫描 |
| 6 | 为让判据变绿而放宽阈值或跳过断言 | 判据向实现妥协即失去等价性结论（ADR-014、R-013） | TG-014；08 §5 变更纪律 |
| 7 | 把闭源二进制（含 `_cor3.dll` 一类传输包）放进产物 | 许可违规且不可重建（SAFE-001） | TG-002 pack 清单 |
| 8 | 静态链接 LGPL 组件 | 剥夺替换权（SAFE-003） | TG-009 链接方式检查 |

**编码原则与测试门的关系**：本节不是「行为规范」，而是判据的输入——评审看三类表，判据看第四列。任一强制条款在实现里找不到对应检查入口，即视为该条款未落地。

## 10. 适用性判定与标准条款对照

**为什么要有这一节**：本包按 GJB/Z 102A 的系统级安全性设计关注点组织，但本项目是「桌面运行时替代」，没有实装硬件、没有分布式协议、没有多用户权限模型。不做适用性判定，要么把不适用的条款硬套成空话，要么漏掉真正该做的条款。判定结果写在两处：本节的「不适用+理由」，以及 §6 的回指索引。

### 10.1 GJB/Z 102A 关注点 → 本包落点 → 适用性

| 关注点 | 本包落点 | 适用性 |
|---|---|---|

| 判定语句安全 | SAFE-006（解码分支）、SAFE-013（入口判定）、[《03-软件设计说明》](03-软件设计说明.md) §4 状态机守卫 | 适用 |

| 用户权限与访问控制 | — | **不适用**：单用户桌面会话，应用以当前用户身份运行，无多角色权限模型（SAFE-017 只约束不提权） |

**判定纪律**：标「不适用」的条目必须给理由且理由要能反驳——「不做」不是说「不用做」。上表三条不适用的共同前提是「本项目不引入该威胁面」；若后续引入（例如支持多用户或远程无障碍），先改本节再改 §2 的 SAFE 落点，不允许只在代码里变化。
