### 1.2 分层与依赖规则

| 层 | 组成 | 允许依赖 | 禁止依赖 |
|---|---|---|---|
| L0 契约 | `exports.txt`、`win32_abi.h`、DUCE 布局表、`FrameworkList` | 无（纯文本与头文件） | 任何实现细节 |
| L1 原生 | `libwpfwin32.so`、`libwpfgfx_linux.so`、`libwpfwic.so`、`libdwlinux.so`、`libSkiaSharp.so` | 系统库：X11、FreeType、HarfBuzz、ICU、Skia、lcms2、GStreamer | 托管程序集；彼此私有符号 |
| L2 托管 | 10 个自产托管件 + 托管适配 | L1，仅经 P/Invoke 与 DUCE | 其他子系统的内部类型 |
| L3 服务适配 | service-adapters 程序集（编入 L2 产物） | L1/L2 + 系统服务（D-Bus、CUPS、GStreamer） | 直接调 X11（必须经 MOD-11/24） |
| L4 包装配 | 两个 pack | L0~L3 产物 | 运行时逻辑 |

- **单向**：L4 ← L3 ← L2 ← L1 ← L0；出现反向依赖视为设计缺陷。
- **原生层之间只经 C ABI**：跨 `.so` 不得传裸指针，改传 §2.3 的句柄。
- **milcore 不感知托管对象模型**：只吃 DUCE 字节流；托管层不出现 `SKCanvas`、`SkSurface` 类型。
- **进程边界即模块边界**：托管侧适配（`PtsCache.Linux.cs`、字体 provider）不进原生仓。

## 2. 关键设计约定

### 2.1 统一错误码

**形态**：`LDP-E-<域>-<序号>`；一个错误码只在一个域定义、只在一个模块产生。

| 域 | 序号段 | 主要来源 | 对外形态 |
|---|---|---|---|
| `ABI` | 001~099 | 入口校验、布局断言、调用约定 | HRESULT 或 `GetLastError` |
| `WIN` | 101~199 | 窗口、消息、输入、剪贴板、DPI | `DWORD`（`GetLastError`） |
| `PACK` | 201~299 | pack 解析、身份、targets | 构建错误行 |
| `DUCE` | 301~399 | 命令解码、资源表、Skia 后端、呈现 | HRESULT |
| `TEXT` | 401~499 | 字体、shaping、行布局、PTS、CFF | HRESULT 或托管异常 |
| `IMG` | 501~599 | WIC 解码、ICC | HRESULT |
| `IME` | 601~699 | 输入法桥 | 日志 + 事件读数 |
| `A11Y` | 701~799 | UIA 桥、MSAA 桥、快照器 | 日志 + 读数 |
| `PRN` | 801~899 | 打印 | 托管异常 + 日志 |
| `MED` | 901~999 | 媒体 | 托管异常 + 状态读数 |
| `INK` | 1001~1099 | Ink | 日志 + 降级读数 |
| `WF` | 1101~1199 | WinForms 兼容层 | 控制台错误行 |
| `APP` | 1201~1299 | applier、判据脚手架 | 进程退出码 |
| `DRM` | 1301~1399 | DRM 桩 | `E_NOTIMPL` + D-001 |

- **翻译边界**：POSIX `errno` 不穿透 ABI，一律在原生入口翻译成上表错误码，再映射成 HRESULT 或 `DWORD`。
- **降级码**：`E_NOTIMPL`（0x80004001）与 `ERROR_CALL_NOT_IMPLEMENTED`（120）只用于降级路径，且日志必须带 `D-` 编号（D-001 已分配，其余待缺陷册分配）。
- **退出码**：0 正常、1 判据红或构建失败、2 契约不符、3 环境缺失（X11/字体/总线）、4 降级完成（SAFE-018）。

### 2.2 统一读数与日志字段

日志为单行 JSON；字段固定，缺 `code` 视为缺陷。

| 字段 | 类型 | 必填 | 约束 | 归属 |
|---|---|---|---|---|
| `ts` | RFC3339 毫秒 | 是 | 可由 Fake 时钟替换 | MOD-06 |
| `lvl` | 枚举 | 是 | `error`/`warn`/`info`/`debug` | 全部 |
| `code` | 字符串 | 是 | `LDP-E-*` 或 `OK`（§2.1） | 全部 |
| `mod` | 编号 | 是 | MOD-xx 或 `-` | 全部 |
| `sm` | 编号 | 否 | SM-xxx 加 `from-to` | §4 |
| `hnd` | 十六进制 | 否 | 按 §2.3 编码 | MOD-11/22 |
| `acc` | 编号 | 否 | 判据上下文 ACC-xxx | MOD-06 |
| `dur_ms` | 整数 | 否 | 单步耗时 | 全部 |
| `degrade` | 编号 | 否 | `D-001`/`K-001`/`none` | 全部 |
| `ext` | 键值 | 否 | **不得含用户输入内容**（SAFE-020） | 全部 |

读数文件（`50-verify/读数/<ACC>/<时间戳>-<序号>.json`）字段与 08 §1.5 完全一致（`acc`/`tg`/`rc`/`verdict`/`started`/`duration_ms`/`env`/`expect_ref`/`diff`/`degrade`），本文件不重定义，只要求落盘格式见 TBL-009。

### 2.3 统一句柄与资源 ID

| 句柄族 | 位宽 | 结构 | 分配者 | 失效码 |
|---|---|---|---|---|
| `HWND` | 32 | kind 4 位（0x1）+ gen 12 位 + index 16 位 | `Win32WindowTable` | `LDP-E-WIN-101` |
| `HDC` | 32 | kind 4 位（0x2）+ gen 12 位 + index 16 位 | `DcTable` | `LDP-E-WIN-108` |
| `HBITMAP` | 32 | kind 4 位（0x3）+ gen 12 位 + index 16 位 | `BitmapTable` | `LDP-E-WIN-109` |
| MIL 资源 | 64 | fam 8 位（0x20）+ gen 16 位 + index 32 位 + 保留 8 位 | `MilResourceTable` | `LDP-E-DUCE-304` |
| WIC 资源 | 64 | fam 8 位（0x30）+ gen 16 位 + index 32 位 + 保留 8 位 | `WicHandleTable` | `LDP-E-IMG-503` |
| DWrite 对象 | 64 | fam 8 位（0x40）+ gen 16 位 + index 32 位 + 保留 8 位 | `DWriteObjectTable` | `LDP-E-TEXT-405` |
| AT-SPI 节点 | 字符串 | 树内稳定路径 `0/1/2` | `TreeSnapshotter` | `LDP-E-A11Y-707` |

- X11 的 `Window`、`GC`、`Visual*` 只存在于 `win32_x11.c` 内部，不上升为托管可见值。
- 句柄 `gen` 每次释放加一；只有复用 index 且 `gen` 不符才算悬垂，否则视为已释放句柄。
- MIL/WIC/DWrite 句柄不跨 `.so` 传裸指针，一律「句柄 + 表查找」；打印 `job-id`（CUPS）与 XPS 作业内部序号分开，禁止混用。

### 2.4 降级四要素

| 要素 | 内容 | 落点 | 例 |
|---|---|---|---|
| 触发条件 | 明确输入或环境 | 缺陷册条目 | 受保护内容路径 |
| 返回码 | §2.1 的明确错误码 | 代码落点旁注释带编号 | `E_NOTIMPL` |
| 用户可见行为 | 控制台行、状态条读数或空白占位 | 界面元素属性表或读数 | 错误行带 `D-001` |
| 缺陷编号 | 缺陷册已分配编号 | [#缺陷登记表](05-数据与清单设计说明.md) §3.8 | D-001、K-001 |

四要素缺一即视为未登记（ACC-030）。本文件不新造 `D-`/`K-` 编号：DRM 用 D-001，milcore 源码缺失用 K-001，其余降级与缺口一律写「编号待缺陷册分配」。

### 2.5 桩件与假件

**定义**：桩件 = 未实现但**显式导出**并返回明确错误的原生入口；假件 = 外部服务的替身，与真件共用同一 IF 契约。

| 名称 | 类别 | 替代什么 | 契约 | 归属 | 偏差登记 |
|---|---|---|---|---|---|
| Fake X11（Xvfb + 事件注入） | 假件 | 真实会话与人工操作 | IF-002 | MOD-06 | 无合成器 → TG-011 须真会话补测（R-008） |
| Fake AT-SPI | 假件 | at-spi2-registryd | IF-051~IF-053 | MOD-06/86 | 事件时序简化 → GAP-012 |
| Fake CUPS | 假件 | 真打印机 | IF-041 | MOD-06/82 | 不出纸，只验作业属性 → GAP-004 |
| Fake ibus | 假件 | 真输入法 | IF-031 | MOD-06/36 | 候选窗仅坐标判据 → GAP-003 |
| Fake 帧源（录制 DUCE 流） | 假件 | 真实布局 | IF-011~IF-014 | MOD-21/23 | 与真布局差异待对拍确认 |
| Fake 时钟 | 假件 | 系统时间 | IF-073 | MOD-06 | 长跑压缩 |
| `PtsStub`、`MsDrmStubs` | 桩件 | 未实现原生入口 | IF-001~IF-006 | MOD-16/85 | 必须 `E_NOTIMPL`，不允许空符号 |

### 2.6 命名与导出纪律

| 项 | 规则 | 检查 |
|---|---|---|
| 导出集合 | 只有 `exports.txt` 列出的符号对外；其余 `-fvisibility=hidden` | TG-001 |
| 内部符号前缀 | 原生内部统一 `ldp_`；不得与 X11/Skia/libpng 符号同名 | 链接期 `-Wl,--exclude-libs,ALL` |

| 托管命名 | 新增类型一律 `internal`；不新增公开 API（应用只认识 WPF API） | 反射扫描 |
| 版本化 | `.so` 带 `SONAME`（如 `libwpfwin32.so.1`）；pack 版本 10.0.x | ACC-004 |
| 文件名 | 自产件与官方同名同身份；`.so` 名按 §1.1 固定 | ACC-003 |

## 3. 模块详细设计

每个模块固定六段：职责与边界、内部结构、关键算法或数据结构、错误与降级、判据注入点、契约关系。所有模块的状态口径统一为「待实现」（§0）。

### 3.1 SYS-1 wpf-port：MOD-01~MOD-06

SYS-1 是上游派生与托管适配层，产物为 10 个自产托管件；它不直接渲染、不直接调 X11。

#### 3.1.1 MOD-01 派生生成

## 4. 状态机设计

### 4.1 通用约定

- **命名**：状态 `S<序号> 名称`；事件用动词短语；守卫写布尔表达式；副作用只写「可见变化 + 落盘读数」；失败码用 §2.1。
- **四条不变量**：①每个状态机只有一个终止态；②未定义事件不改状态，只记日志并计数；③终止态无出边，收到事件返回「句柄失效」类错误；④降级路径必须进 `Degraded`/`Error` 态，不许原地静默。
- **可观测**：每次转移写一条 `info` 日志（`sm`、`from`、`to`、`ev`、`dur_ms`）；状态读数入口为 `ldp_sm_state(sm_id)`。
- **持久化**：仅 SM-005（打印作业）与 SM-008（applier 戳）落盘，其余为内存态，进程退出即消失。

## 5. 并发、句柄与幂等

| 执行体 | 归属 | 可触及对象 | 规则 |
|---|---|---|---|
| Dispatcher 线程 | wpf-port | 全部托管对象与 `HWND` 表 | V1 中唯一可调 X11 与 Skia 的线程 |
| X11 事件线程 | MOD-11/12 | `Win32WindowTable`、消息队列 | 只做翻译与入队，不回调托管 |
| D-Bus 回调线程 | MOD-36/81 | IME 会话表、桥节点镜像 | 投递到 Dispatcher，不直接改树 |
| GStreamer 回调线程 | MOD-83 | 媒体状态快照 | 只更新快照并投递事件 |
| 判据进程 | MOD-05/06 | 读数目录 | 串行执行，读数目录名带时间戳 |
| applier | MOD-01 | 派生树 | 单进程串行，禁止并行写派生树 |

- **锁顺序**（只能单向）：`HWND` 表 → MIL 资源表 → 帧队列 → IME 会话表；反向加锁视为缺陷，debug 构建下 fail-fast（`LDP-E-ABI-007`）。
- **不在持锁时回调**：持锁期间禁止调用托管代码、D-Bus、CUPS；必须先把数据复制出临界区。
- **句柄**：分配与释放都在所属表内完成；跨线程只传值不传指针；句柄表本身用读写锁保护（§2.3）。
- **幂等**：
  - applier：`stamp.json` 命中即整树跳过（ACC-005）。
  - pack：资产按名排序、时间戳取 `SOURCE_DATE_EPOCH`，两次组装 sha 相同（NF-005）。
  - 读数：目录名 `<时间戳>-<序号>`，重复执行不覆盖旧读数（TBL-009）。
  - 打印：去重键 `(queue, doc_sha, page_count)`，重复提交不产生第二个作业；消息 `SendMessage` 嵌套上限 8，超限返回错误而不是递归加深（§4.3.3）。

## 6. 错误处理与日志

| 场景 | 处理 | 返回 | 读数 |
|---|---|---|---|
| 参数非法 | 入口即拒，不进入解码或绘制 | 域内码（§2.1） | 一条 `error` 日志 |
| 未实现入口 | 显式导出，返回 `E_NOTIMPL` | `E_NOTIMPL` + 缺陷册编号 | 缺口计数 |
| 外部服务缺失 | 明确报错或降级，不静默 | 域内码 + 退出码 3 | `degrade` 字段 |
| 契约不符 | 构建期判红，不进产物 | `LDP-E-ABI-004/005` | TG-001 差异条数 |
| 判据红 | 落读数、保留旧读数 | 退出码 1 | TBL-009 |

- **日志分级**：`error` 只给失败与降级；`warn` 给拒绝与重试；`info` 给状态转移与关键读数；`debug` 默认关闭（SAFE-020）。
- **禁止静默**：任何「返回空、返回默认值、跳过一步」都必须有日志与缺陷册编号，否则按 ACC-030 判红。
- **不记输入内容**：`ext` 字段禁止写入文本值、剪贴板内容、密码框内容（SAFE-020）；判据需要文本时只记长度与 sha。
- **退出码**：见 §2.1（0/1/2/3/4），由 SAFE-018 约束。

## 9. 软件单元与 CSCI 划分

> CSCI 是 GJB 438C-2021 里的「计算机软件配置项」。本文只把它当**交付单元的划分标签**（`CSCI-PORT`、`CSCI-SHIM`…），不是新的受管编号族：受管编号仍只有 ADR/MOD/SYS/R 与本文定义的 SM-001~SM-008。CSCI 标签不入 [#设计模型](../model/model.json)；若要升为首选名，先由[《术语表》](../../00-admin/术语表.md) 维护者登记，再在正文使用。

| CSCI 部件 | 包含模块 | 语言 | 交付形态 | 单元测试归属（TG） |
|---|---|---|---|---|
| `CSCI-PORT` | MOD-01~MOD-06（6 个） | C# / MSBuild | 10 个自产托管件 + applier 脚本 | TG-001、TG-002、TG-008、TG-014 |
| `CSCI-SHIM` | MOD-11~MOD-17（7 个） | C | `libwpfwin32.so` | TG-001、TG-004、TG-005、TG-011、TG-013 |
| `CSCI-MIL` | MOD-21~MOD-25（5 个） | C#（AOT 导出 C ABI） | `libwpfgfx_linux.so` | TG-001、TG-003、TG-011 |
| `CSCI-TEXT` | MOD-31~MOD-36（6 个） | C# + C | `libdwlinux.so` + 托管部分 | TG-005、TG-006、TG-010 |
| `CSCI-WIC` | MOD-41、MOD-42（2 个） | C | `libwpfwic.so` | TG-007 |
| `CSCI-PACK` | MOD-51~MOD-53（3 个） | MSBuild | 2 个 NuGet 框架包 | TG-002、TG-008 |
| `CSCI-WINFORMS` | MOD-61~MOD-63（3 个） | C# | 兼容层程序集 | TG-012、TG-013 |

**覆盖核对**：6+7+5+6+2+3+3+6 = 38，与[《概要设计》](../概要设计.md) §4 的 38 个 MOD 一一对应，无重复、无遗漏；每个 MOD 的设计小节在 §3，判据注入点在 §8，两处都由[#编号检查器](../checks/check-design-ids.mjs) 按 [#设计模型](../model/model.json) 的 `moduleGroups` 核对。

**为什么按进程边界划 CSCI（ADR-003）**：三个契约（P/Invoke C ABI、DUCE 字节流、pack 清单）就是进程与交付边界，CSCI 与契约对齐后，单元测试边界与桩件边界同时确定：

| 交付形态 | 单元测试边界 | 桩件边界 | 明确不测什么 |
|---|---|---|---|
| 托管程序集（`CSCI-PORT`、`CSCI-TEXT` 的托管部分、`CSCI-WINFORMS`） | CoreCLR 内的 xUnit；不连 X11、不装 pack | D-Bus 对端用 `Fake AT-SPI`、`Fake ibus`；时间用 `Fake 时钟` | 不测 X11 语义（属 `CSCI-SHIM`） |
| 原生 `.so`（`CSCI-SHIM`/`CSCI-MIL`/`CSCI-WIC`、`CSCI-TEXT` 的 C 部分） | `dlopen` + 直接调 C ABI，**不加载 WPF**；断言返回值与结构体布局 | X11 用 `Fake X11`；DUCE 输入用 `Fake 帧源` | 不测 WPF 对象模型（原生层不感知它） |
| 框架包（`CSCI-PACK`） | 构建即测试：`dotnet build` + 清单 diff | 无需桩件 | 不测运行时行为（属其他 CSCI） |
| 兼容层（`CSCI-WINFORMS`） | 样本进程启动 + 控件动作；缺失控件负向断言 | `Fake AT-SPI` | 不测设计器/ActiveX（ADR-011 明确不做） |

**划分带来的两条纪律**：①跨 CSCI 只能经 IF 契约说话，CSCI 之间不共享内部符号；②同一契约变更必须同时改两端 CSCI 与对拍读数，不允许单侧改（[《05-数据与清单设计说明》](05-数据与清单设计说明.md) §5）。

## 10. 设计决策清单

以下是本文档在 ADR 框架内做的实现级决策。它们**不新增 ADR**，只把 ADR 落到可施工的粒度：

| 决策 | 理由 | 影响模块 | 对齐 ADR |
|---|---|---|---|
| 托管层只加补丁，不改 API 语义 | 重写托管层等于重写 WPF，与「源码级重编」等价性判据冲突 | MOD-01/02 | ADR-001、ADR-002 |
| 补丁只写 applier，派生树手改无效 | 派生树必须可再生，评审对象是 applier 不是产物 | MOD-01/05 | ADR-002 |
| 错误码按 `LDP-E-<域>-<序号>` 分域（14 域） | 同域同源，便于按域统计与定位；不穿透 POSIX `errno` | 全部 | ADR-012 |
| 句柄表一进程一份，不按窗口分表 | Win32 句柄本就是进程级；位图与字体面要跨窗口共享 | MOD-11/13/22 | ADR-003 |
| DUCE 解码单线程、按批提交 | 命令流有序；多线程解码要重排指令，得不偿失 | MOD-21/24 | ADR-003、ADR-004 |
| 行布局放托管侧，原生只做 shaping 与轮廓 | LineServices 源码不可得（R-002）；托管侧可单测 | MOD-33/34 | ADR-007 |
| 字体回退链按「请求族」缓存，容量按 LRU 收敛 | 回退查询在热路径；按族命中率高，缓存条目可控（容量见 02 §15.2） | MOD-31 | ADR-007 |
| IME 桥异步投递事件到 UI 线程 | D-Bus 回调不得同步等 UI 线程，否则死锁（02 §12） | MOD-36 | ADR-008 |
| 树快照按树序编号 `path`，不用坐标 | 坐标随 DPI、字体、窗口尺寸漂移，树序稳定 | MOD-86 | ADR-015 |
| 读数 JSON 四值判定（`PASS`/`FAIL`/`SKIP`/`DEGRADED`） | `SKIP` 不得混入 `PASS`，否则统计口径失真 | MOD-05/06 | ADR-014 |
| 桩件与真件共用同一 IF 契约 | 否则「桩上绿、真机红」无法归因 | MOD-06 + 全部 | ADR-014 |
| applier 幂等以产物 sha 判定 | sha 一致是幂等唯一可复算证据 | MOD-01/05 | ADR-002 |
| WinForms 缺失控件输出空白占位 + `D-` 编号，进程不退出 | 不许崩溃、不许静默（DQ-003） | MOD-62 | ADR-011 |
| 无合成器时走 `DwmIsCompositionEnabled=false` 路径 | 不伪造合成能力，降级要说出来 | MOD-11/24 | ADR-005 |
| PTS 缺口统一返回 `E_NOTIMPL`，不按声明名反推参数语义 | 反推等于猜语义，且猜错无人能发现 | MOD-16/34 | ADR-007、ADR-012 |
| 每个契约文件改动必须同时触发 TG-001 对拍 | 契约漂移是本项目最大隐性风险（R-007） | MOD-17/21/51 | ADR-003 |

**读表口径**：本表只写「本文档定的实现级取舍」；架构级取舍（为什么用 Skia、为什么用 X11、为什么不做二进制兼容）一律看[《概要设计》](../概要设计.md) §3，本文不重复结论、不新造 ADR。

## 11. 人机界面与无障碍设计引用

本仓没有自研界面，界面是 WPF 样本工程画出来的那一屏。本文只定义「无障碍树怎么产生、怎么可测」，界面本身的区域与元素期望在[《界面设计说明》](界面设计说明.md)，覆盖与分叉处置在[《08-判据先行与界面检测设计说明》](08-判据先行与界面检测设计说明.md) §3。

| 界面关注点 | 本文件落点 | 设计说明落点 | 判据 |
|---|---|---|---|
| 角色映射（UIA `ControlType` → AT-SPI role） | MOD-81，按 [#无障碍角色映射表](05-数据与清单设计说明.md) §3.12 查表 | [《界面设计说明》](界面设计说明.md) §0.3、§9.1 | TG-012、ACC-027 |
| 名称（`AutomationPeer.GetName()`） | MOD-81 语义投影，不拼接、不翻译 | 各 SCR 元素属性表「名称期望」列 | TG-012 |
| 状态位（`enabled`/`focused`/`selected`/`checked`/`expanded`…） | MOD-81 状态映射 | 各 SCR「状态期望」列 | TG-012 |
| 动作（`click`/`set-text`/`select`/`expand`/`focus`/`scroll`） | MOD-81 白名单 + MOD-86 观察点（IF-053） | 各 SCR「动作」列 | TG-012 |

| 事件（焦点/状态/属性/结构/文本变化） | MOD-81 事件投影（IF-052） | GAP-012 的粒度对齐 | TG-012 |

**三条实现约定**：

1. **界面不自己画无障碍树**：树由 WPF `AutomationPeer` 语义投影而来，桥不新增视觉节点、不伪造控件、不把日志文本塞进树。要暴露的读数（DPI、合成状态）必须是样本自己画出来的 WPF 元素（如 SCR-01 状态条），不是桥造的假节点。
2. **首帧后 1 s 内必须抓到完整快照**：超时即判 `FAIL`（不是 `SKIP`）；快照失败允许 3 次重试、退避 200 ms（GAP-010 的竞态），仍失败记 `FAIL` 并把最后一份半截快照留在读数目录。
3. **结构 diff 只比六列**：`path` + `role` + `name` + `states` + `actions`（加 `value`、`relations`），`bounds` 单列比对、不参与结构 diff。判定口径见[《08-判据先行与界面检测设计说明》](08-判据先行与界面检测设计说明.md) §3.2~§3.3。

**与界面实现相关的缺口落地**（六条，逐条写本模块怎么降级）：

| 缺口 | 本模块落地方式 |
|---|---|
| GAP-001 合成器状态无标准属性 | MOD-86 不在树里造非标准属性；由样本以 label 文本暴露 `composite=`，MOD-81 只投影真实元素 |
| GAP-002 `TabItem`/`RadioButton` 选中态落 `selected` 或 `checked` | MOD-81 两个状态位都置，TBL-012 登记差异；结构 diff 两者皆接受 |
| GAP-003 IME 候选窗不在树内 | MOD-36 只管预编辑/提交/取消事件；候选窗位置走坐标读数 + 帧判据，不进树 |
| GAP-008 `RibbonGroup` 无对应角色 | MOD-81 映射为 `panel`，差异登记在 TBL-012；期望侧按 `panel` 比对 |
| GAP-009 WinForms 缺失控件占位无标准角色 | MOD-62 输出含 `D-` 编号的占位节点，MOD-63 投影为 `filler` 且 `name` 含缺陷编号 |
| GAP-012 `value-changed` 粒度不对齐 | MOD-81 对同值重复事件做 100 ms 合并；判据按「最终值 + 至少一次事件」判定 |
