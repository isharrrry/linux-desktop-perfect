## 2. 单一事实源规则

同一内容只在一处定义，其他文件只引用；发现两处各写一套，以「唯一来源」为准并回改别处（[《01-设计总纲与设计基线管理》](01-设计总纲与设计基线管理.md) §2 规则 B）。

| 内容 | 唯一来源 | 其他文件怎么写 |
|---|---|---|
| 需求与验收判据（REQ/ACC/NF/XIF/DQ） | [《需求与验收判据文档》](../../20-spec/需求与验收判据文档.md) | 只写编号，不重述内容 |
| 架构决策、模块、系统、风险（ADR/MOD/SYS/R） | [《概要设计》](../概要设计.md) §3/§4/§9 | 只写编号 |
| 字段级契约（IF） | [《04-接口设计说明》](04-接口设计说明.md) | 只写「见 IF-xxx」 |
| 清单与表结构（TBL） | [《05-数据与清单设计说明》](05-数据与清单设计说明.md) §3 | 只写「见 TBL-xxx」 |
| 安全要求（SAFE） | [《06-安全性设计支撑材料》](06-安全性设计支撑材料.md) §2 | 只写编号；06 是安全要求唯一正文 |
| 界面元素属性表（SCR/GAP） | [《界面设计说明》](界面设计说明.md) §1~§9.3 | 只写「见 SCR-xx」；图由表生成 |
| 测试门与判据落点（TG） | [《08-判据先行与界面检测设计说明》](08-判据先行与界面检测设计说明.md) §2/§4 | 只写「见 TG-xxx」 |
| 模块实现细节（SM） | [《03-软件设计说明》](03-软件设计说明.md) §3/§4 | 只写章节号或编号 |
| 名称与引用写法 | [《术语表》](../../00-admin/术语表.md)、[《引用与名称规范》](../../00-admin/引用与名称规范.md) | 不另立写法 |

## 4. 详细设计细化规则

- **位置**：模块详细设计写在 [《03-软件设计说明》](03-软件设计说明.md) §3 对应 MOD 小节，不另立文件或目录；其他包只引章节号与 MOD 编号。
- **结构**：每节固定六段——职责与边界、内部结构、关键算法或数据结构、错误与降级、判据注入点、契约关系。可加数据结构与安全性说明，不得删减六段。
- **状态口径**：模块状态只有「待实现／实现中／待对拍确认」三种；判据状态只有「红／绿」，且红读数必须落盘。**没有「已支持」这个词**（[《01-设计总纲与设计基线管理》](01-设计总纲与设计基线管理.md) §2 规则 A）。
- **偏差**：只能在 07 §5 记一行更改，不得静默改 ADR/MOD 职责边界；要改架构先回到概设新增 ADR。
- **单一事实源**：接口引 04、清单引 05、安全引 06、界面引 [《界面设计说明》](界面设计说明.md)、判据引 08；细化时不就地拆文件。
