# 本体说明

> 本目录是 LinuxDesktopPerfect 的**运行时本体**（对象模型）全部内容。**入口就是本文件**：先读完它，不必先翻 `ontology.yaml`。
>
> 目录：[#业务本体](ontology.yaml)｜[#本体模型页](本体模型.html)（单文件、双击即开）｜[#本体校验器](本体校验.py)（13 条判据 + 生成模型页）｜[#本体渲染校验器](渲染校验.mjs)（14 条页面断言）｜[《本体构建记录》](本体构建记录.md)（怎么建出来的、有哪些冲突与裁决）

---

## 1 这是什么

LinuxDesktopPerfect 的**运行时对象模型**：24 个类、26 条关系、40 条规则、11 个动作、18 条术语，外加 38 个模块到类的映射。它回答的不是「代码长什么样」，而是：

- 这个运行时里有哪些**对象**（会话、窗口、消息、命令流、句柄、字形运行、无障碍节点、判据读数……）；
- 这些对象**怎么连**（窗口提交命令流、命令流引用句柄、视觉树投影成无障碍节点……）；
- 什么**条件触发什么动作**（无合成器怎么办、PTS 入口缺失怎么办、判据放宽怎么办）。

| 产物 | 文件 | 规模 |
|---|---|---|
| 本体 | [#业务本体](ontology.yaml) | 24 类／26 关系／40 规则／11 动作／18 术语／38 模块映射／12 裁决／12 排除 |
| 交互式模型页 | [#本体模型页](本体模型.html) | 单文件、无外链；五个页签（类与关系／规则／动作与术语／裁决与排除／校验报告） |
| 校验器 | [#本体校验器](本体校验.py) | 13 条判据，顺带重生成模型页 |
| 渲染校验器 | [#本体渲染校验器](渲染校验.mjs) | 从页面内联数据反解 14 条断言（不依赖浏览器） |
| 构建记录 | [《本体构建记录》](本体构建记录.md) | 规模、筛除、冲突组、12 条裁决、待裁决项 |

## 2 与既有四张表示的分工（这条最先看）

本仓原有的四张表示在[《引用与名称规范》](../../00-admin/引用与名称规范.md) §4 已定：名称口径、需求编号、设计编号、契约文件。**本体是第五张，且不新增语义**——它是这四张的**对象化视图与关联图**。

| 表示 | 回答什么 | 权威在哪 | 本体怎么用它 |
|---|---|---|---|
| 名称口径 | 这个东西叫什么、不叫什么 | [《术语表》](../../00-admin/术语表.md) + [#名称清单](../../30-design/model/names.json) | 只落 `terms` 段，异名与出处照抄，不自造同义词 |
| 需求编号 | 要什么、怎么验收 | [《需求与验收判据文档》](../../20-spec/需求与验收判据文档.md) | 规则 `source` 里引 `REQ-FN`/`ACC`，不重述需求正文 |
| 设计编号 | 怎么建、边界在哪 | [《概要设计》](../../30-design/概要设计.md) + 设计文档包 | 类的 `source` 逐条指向 `MOD`/`ADR`/章节；`modules` 段把 38 个 MOD 映到类 |
| 契约文件 | 原生层边界长什么样 | `exports.txt`、`win32_abi.h`、DUCE 布局表、`FrameworkList` | `C014` 只声明「有这四个文件」，字段一律回[《05-数据与清单设计说明》](../../30-design/设计文档包/05-数据与清单设计说明.md) |
| **本体**（本目录） | 有哪些对象、什么条件触发什么动作 | 本目录 `ontology.yaml` | 消费方：规则引擎、知识库、影响分析、Agent 检索 |

**三条纪律**：

1. **本体不是接口清单**。`C007 DUCE 命令流` 是[《04-接口设计说明》](../../30-design/设计文档包/04-接口设计说明.md) §3 的对象化视图，不含字段定义；查字段回 04，本体只说明「命令流这个类该被哪些规则引用」。
2. **本体不是设计文档的替代品**。类属性只写「运行时对象身上有什么」，不写实现细节；`source` 指错或缺失即视为本体缺陷。
3. **冲突以被引文档为准**。本体里发现两处说法不一致，记进 `decisions` 段与[《本体构建记录》](本体构建记录.md) §3，去改设计文档，不在本体里二选一。

## 3 怎么用

```bash
# 一条命令做两件事：跑 13 条判据 + 重生成交互式模型页
python3 30-design/ontology/本体校验.py

# 可选：从模型页内联数据反解 14 条断言（不启动浏览器，CI 可跑）
node 30-design/ontology/渲染校验.mjs
```

校验通过后输出 `ALL_CHECKS_PASSED`，并重写 `30-design/ontology/本体模型.html`。模型页无外部依赖，双击就能开。

**模型页五个页签**：

| 页签 | 看什么 |
|---|---|
| 类与关系 | 24 个类的布局图 + 26 条关系；点节点看属性、入边出边、相关规则 |
| 规则 | 40 条规则，可按 `medium`/`low` 筛选、全文搜索 |
| 动作与术语 | 11 个动作（trigger→规则、target→类、`api_hint` 为空标「待定」）＋18 条术语的归一对照 |
| 裁决与排除 | 12 条 decisions 与 12 条 excluded（被筛掉的概念与原因） |
| 校验报告 | 本次 13 条判据的逐条结果与本体元信息（版本、`built_at`、`degrade_note`、重建触发条件） |

**`ontology.yaml` 顶层段**：

| 段 | 内容 | 怎么读 |
|---|---|---|
| `ontology` | 名称、域、版本、`built_at`、`inputs`、`degraded_note`、`regenerate_when` | 先看 `regenerate_when` 判断手上这份还算不算数 |
| `classes` | 24 个类，每个有 `id`(C001)、`id_en`、`name_zh`、`source`、`description`、`properties` | `source` 末尾指到设计文档章节 |
| `relations` | `{from,to,predicate,description}`，`predicate` 是 2~4 字中文动词 | `from`/`to` 必须能在 `classes[].id` 找到，悬空即错 |
| `rules` | `condition`/`then`/`source`/`confidence`/（可选 `conflict_group`+`conflict_reason`） | `confidence` 最高只到 `medium`，见 §5 |
| `actions` | `name`/`trigger`/`target`/`api_hint` | `api_hint` 为空说明接口还没定 |
| `terms` | `canonical`/`variants`/`sources` | 查「这东西还有哪些叫法」 |
| `modules` | 38 行 `MOD-xx` → 类 | 校验器与概设 §4 交叉核对，缺一个即红 |
| `decisions` | `D01~D12`，逐条处置建本体时发现的文档冲突 | 这一段最有价值，见 §7 |
| `excluded` | 12 条被筛掉的概念与原因 | 判断「某概念为什么没进本体」 |

## 4 怎么重生成

**触发条件**（与 `ontology.yaml` 的 `regenerate_when` 同口径）：[《概要设计》](../../30-design/概要设计.md) 的 ADR/MOD/SYS/R 增删、04 的 IF 增删、05 的 TBL 增删、[《界面设计说明》](../../30-design/设计文档包/界面设计说明.md) 的 SCR/GAP 增删、08 的 TG 增删、[《已知坑与降级清单》](../../70-operate/已知坑清单.md) 的编号变化。**纯文字修订、改链接、改文档名不触发。**

**三步人工流程**（本项目不做 LLM 抽取流水线）：

1. **对照**：按上面触发条件列出变化的编号，在 `classes`/`relations`/`rules`/`modules` 里找到受影响项。
2. **改本体**：只改受影响项；新增类/规则要补 `source`，删条目要进 `excluded` 并写原因。
3. **跑校验**：`python3 30-design/ontology/本体校验.py` 必须 `ALL_CHECKS_PASSED`；`node 30-design/ontology/渲染校验.mjs` 必须 14/14；再跑 [《00-文档包总览与评审检查单》](../../30-design/设计文档包/00-文档包总览与评审检查单.md) §3 的五条门禁。

**为什么没有三阶段抽取流水线**：本仓设计文档已经是机器可校验的结构（编号族 + [#设计模型](../../30-design/model/model.json) + 五条检查器），抽取不需要 LLM；引入抽取流水线只会多一层不可复算的中间产物。本体的价值在**对象与规则**，不在「从 40 篇 md 里捞词」。

## 5 两条硬约束

**① 无实测读数，规则全部是规格推导。** `degraded_note` 原文：

> 本项目尚无任何实测判据读数（实现未开始），本体里的规则全部由设计文档推导，没有一条被运行验证过；因此 rules.confidence 不得为 high，最多 medium。

后果：**40 条规则无一为 `high`**（37 `medium` ＋ 3 `low`）。这不是保守，而是事实——没有一条规则被真实运行验证过。将来接上 `50-verify/读数/` 的真读数，才谈得上升级置信度。

**② 规则引用未闭合项的，置信度只能 `low`。** 目前三条：`R036`（候选窗不在树内，GAP-003 未闭合）、`R038`（PresentationNative 口径，D06 已裁决但实读数还没有）、`R039`（FrameworkList 件数，D07 已裁决仍待 TG-001 对拍）。口径裁决不等于实现验证，故保持 `low`。

## 7 新增/修改本体时守什么

1. **类 ≤ 25、规则 ≤ 40**。超了按「是否被规则引用 + 是否有契约落点 + 是否可判据化」三项筛，被筛的记进 `excluded` 并写原因。
2. **每个类必须有非空 `properties`**，属性 `{key, type, description}`；`key` 用 `snake_case`；`type` 只用 `string|integer|float|boolean|datetime|enum|array|object`；用 `enum` 必须给 `enum_values`。
3. **不编造属性或接口**。`api_hint` 只有在 04 的 IF 表里查得到时才写，否则留空（模型页显示「待定」）。
4. **悬空引用为 0**：`relations.from/to`、`actions.target`、`modules.classes` 必须指向已定义类。
5. **id 连续不跳号**：类 `C001…`、关系 `RL001…`、规则 `R001…`、动作 `A001…`、裁决 `D01…`。
6. **冲突不静默丢弃**：同一条件有不同结论时写两条规则，各加 `conflict_group` 与 `conflict_reason`，并在[《本体构建记录》](本体构建记录.md) 记裁决。
7. **不新增语义**：类与规则必须能指到设计文档的章节或编号；指不到就是「本体在编故事」。
8. **改完跑三样**：`python3 30-design/ontology/本体校验.py`（`ALL_CHECKS_PASSED`）、`node 30-design/ontology/渲染校验.mjs`（14/14）、[《00-文档包总览与评审检查单》](../../30-design/设计文档包/00-文档包总览与评审检查单.md) §3 的五条门禁。
