# 程序化操作 SourceTree 的 5 条使用方规则

> 用反射/IL 注入方式驱动 SourceTree（不开鼠标、不点按钮）时，下面 5 条是**必须满足的前置**。
> 每条都附「代码片段 + 验证判据 + 不满足时的现象」。顺序不能乱：**① → ② → ③ → ④ → ⑤**。
>
> 参考实现：[Helper.cs](profiles/Helper.cs)。坑的完整证据见[《已知坑与降级清单》](../../70-operate/已知坑清单.md)对应 K 号。

## 规则总览

| 顺序 | 规则 | K 号 | 不满足时 |
|---|---|---|---|
| ① | 反射注入 Dvcss 安装配置 + 造 `<home>/cmd\git.exe` 布局 | K-1413 / K-1415 | `GetHandler` 为 null ⇒ 任何 VCS 操作都不执行，列表恒空 |
| ② | `AddOrActivate(path, mode, null)` 打开仓库 | K-1373 | 无 tab、无视图 |
| ③ | **补调 `RepositoryMonitorManager.ActivatedTab(path)`** 启用文件监控 | K-1445 | 写文件后列表不自动刷新（`staged` 恒 0） |
| ④ | 切视图要显式 `NavigateToView(Log, null)` 或设 `CurrentRepoView=1` | K-1421 | `AddOrActivate(..., Log, ...)` 后 UI 仍停在「文件状态」 |
| ⑤ | `LoadNextLogBatchFrom(0,500)` 在切视图之后调，读数放 `DispatcherTimer` 里 | K-1419 / K-1420 | History 列表空；`Thread.Sleep` 会阻塞回填、后台线程读会核心转储 |

## ① Dvcss 配置注入 + `cmd\git.exe` 布局（K-1413 / K-1415）

**为什么**：`SourceTree.Dvcss.Git::GetHandler` 第一步读 `CurrentInstallationConfiguration`，为 `null` 就直接 `ret null`（K-1413）；该字段只在「安装/切换版本」的 UI 路径才被写，启动路径不写。

```csharp
var vm   = (object)window.DataContext;                       // MainWindowViewModel
var dvcs = Prop(vm, "DvcssManager").GetType().GetMethod("GetDvcs").Invoke(Prop(vm, "DvcssManager"),
             new object[] { 0 /* RepoType.Git */ });
var cfgMgr = Prop(vm, "ConfigurationManager");               // IConfigurationManager
var verCfg = Activator.CreateInstance(
    Type.GetType("SourceTree.Dvcss.GitVersionOneConfiguration, SourceTree.Dvcs.Git"),   // ctor 是 public
    new object[] { cfgMgr });
// 3 参 ctor：homePath / actualVersion / IDvcsVersionConfiguration（2 参或 1 参会因 VersionConfiguration 为 null 抛 NRE）
var instCfg = Activator.CreateInstance(
    Type.GetType("SourceTree.Model.Dvcss.DvcsInstallationConfiguration, SourceTree.Api.Dvcs"),
    new object[] { Environment.GetEnvironmentVariable("GV_HOME") ?? "/usr", "2.30.0", verCfg });
Field(dvcs.GetType(), "<CurrentInstallationConfiguration>k__BackingField").SetValue(dvcs, instCfg);
```

**布局**：`get_ExePath` 的 IL 硬编码 `"cmd\git.exe"`（反斜杠是字面量，Linux 上会变成一个含 `\` 的**文件名**）⇒ 必须存在 `<GV_HOME>/cmd\git.exe`。用[#dvcss-prereq.mjs](../../40-build/appliers/dvcss-prereq.mjs) 一条命令造出（D 链，见[《交付说明》](../../60-deliver/README.md)）。

**判据**：`dvcs.GetType().GetMethod("GetHandler").Invoke(dvcs, null) != null` 打印 1。

## ② + ③ 打开仓库 **并启用监控**（K-1373 / K-1445）

```csharp
var rtc = Prop(vm, "RepositoryTabContainer");                 // RepositoryTabContainerViewModel
var add = rtc.GetType().GetMethod("AddOrActivate");           // 返回 void，不能 pop（K-1373）
add.Invoke(rtc, new object[] { repoPath, Enum.ToObject(add.GetParameters()[1].ParameterType, 0), null });

// ⚠️ 必须补这三步：AddOrActivate 不注册 watcher（K-1445）
var mm = Field(vm.GetType(), "<RepositoryMonitorManager>k__BackingField")?.GetValue(vm)
      ?? Prop(vm, "RepositoryMonitorManager");
mm.GetType().GetMethod("ActivatedTab").Invoke(mm, new object[] { repoPath });
mm.GetType().GetMethod("RefreshFileSystemMonitoring").Invoke(mm, null);
mm.GetType().GetMethod("SetFileWatcherStatus").Invoke(mm, new object[] { repoPath, true });
Prop(mm, "RepoMonitor")?.GetType().GetMethod("Resume")?.Invoke(Prop(mm, "RepoMonitor"), null);
```

**判据**：进入 timer 后往仓库写文件并 `git add`，**3 秒内** `StagedFileList.Count` 由 0 变 1，且 `git status` 调用次数随之增加（K-1445：补调后 3/3，未补调 1/2~3/5 波动）。

**不满足的现象**：`staged` 恒 0，手动 `RefreshStatus()` 才变 1（K-1440/K-1442）。

## ④ 切视图（K-1421）

```csharp
var tab = Prop(rtc, "SelectedRepoTabViewModel");
tab.GetType().GetMethod("NavigateToView").Invoke(tab, new object[] {
    Enum.ToObject(<RepoViewMode 类型>, 1 /* Log */), null });
// 或：tab.GetType().GetMethod("set_CurrentRepoView").Invoke(tab, new object[] { Enum.ToObject(..., 1) });
```

**判据**：`CurrentRepoView` 读出为 `Log(1)`；**但注意**：`set_CurrentRepoView` 只触发属性变更、不重建视觉树，UI 上是否切换要看截图。

**不满足的现象**：`AddOrActivate(path, Log, null)` 之后 `CurrentRepoView` 仍是 `FileStatus`（K-1421）。

## ⑤ 拉 History 数据（K-1419 / K-1420）

```csharp
// 必须在 ④ 之后调用；async void，自身会切回 UI 线程做回填
var logVm = Prop(tab, "LogVM");
logVm.GetType().GetMethod("LoadNextLogBatchFrom").Invoke(logVm, new object[] { 0, 500 });

// 读取必须放在 DispatcherTimer 的回调里（UI 线程），且不要 Thread.Sleep
new DispatcherTimer(TimeSpan.FromSeconds(3), DispatcherPriority.Background,
    (s, e) => Log("[tick] LogRows=" + Prop(logVm, "LogRows")?.GetType()
        .GetProperty("Count")?.GetValue(Prop(logVm, "LogRows"))), window.Dispatcher);
```

**判据**：`LogRows.Count` 从 1（`AddLoadingRow` 的占位行，K-1418）变 ≥2（有 16 个历史提交时实测 17~19），且截图里 History 面板列出提交行。

**不满足的现象**：`LogRows.Count` 恒 1；若用 `Thread.Sleep` 等则回填 continuation 被阻塞；若从后台线程读 `ObservableCollection` 则核心转储（K-1419）。

## 附加：等待/事件相关（K-1441 / K-1444）

- `cmd\git.exe` 用**延迟退出 wrapper**（`/usr/bin/git "$@"` → `sleep 0.15` → `exit $rc`），否则出现 `"git status"失败 … the process has exited` 的竞态（K-1441/K-1442）；
- `WaitForMultipleObjectsEx` 在 shim 侧已是「最小降级」（`WAIT_TIMEOUT` + `usleep`），不再抛 `Win32Exception(50): No CSI structure`（K-1444）。

## 立即可复跑的最小骨架

见同目录 [Helper.cs](profiles/Helper.cs)：把 `Injected::Run(window)` 插到 `MainWindow_Loaded` 开头即可复现 ①~⑤ 全流程（注入器参考 `40-build/appliers/loglabel-brush/` 的 Cecil 写法）。
