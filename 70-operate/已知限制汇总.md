# 已知限制汇总（2026-11-02，第 715 轮）

> 本文只记录**有实测证据、且经判定为架构性/非单轮可修**的限制。
> 每条都给出：现象 → 证据 → 根因 → 为什么判定为限制。

## L-1 客户区渲染空白（客户区 4 色）

- **现象**：SourceTree 主窗口能创建（`WID=8388613`）、AT-SPI 可枚举，但客户区截图 **4 色 / 9172 字节**（空白）
- **证据**：`sourcetree-shots/st-20-main-window-9172.png`；像素分析 `len(set(crop((0,60,w,h)).getdata())) == 4`
- **根因**：`/wpf/src` 的 shim **没有渲染后端**（无 `MilPresent` / `XPutImage` / `XCopyArea`），WPF 画了但像素永远到不了 X11 窗口（K-740 / K-747）
- **判定为限制**：需要实现完整的 X11 渲染后端（约 500–2000 行 C：像素格式转换、脏区、`SHM`/`XPutImage` 路径）

## L-2 UIA 控件树只有窗口级（≥30 有 name 控件 / ≥5 类未达成）

- **已达成的部分**：**10 个控件 / 6 个有 name**（`application` + `frame` 两类）
  - 证据：`sourcetree-shots/proof-uia-dumptree.json`（2339 B）、`proof-uia-sourcetree.json`（1363 B）
  - 可复现：`dump-tree.dll --json --bus <bus>` / `gdbus call ... GetChildren`
- **未达成的部分**：目标要求 **≥30 个有 name 控件 + ≥5 类**（menu/toolbar/button/text/list/tab/status）
- **根因（15 层实证链，K-866 … K-907）**：
  ```
  AT-SPI 注册 ✓
    → dispatch ✓（proc 非 NULL）
    → SubclassWndProc ✓（msg=0x3D）
    → HwndWrapper.WndProc ✓（msg=0x3D）
    → HwndTargetFilterMessage ✓（msg=0x3D ×2；第 2 次 _hwndTarget != null 且 IsUsable=True）
    → HwndTarget.HandleMessage ✓（msg=61）
    → ❌ if (IsDisposed) return;   // HwndTarget.cs:1013
    → CriticalHandleWMGetobject（未调用）
  ```
- **结论**：`WM_GETOBJECT` **完整抵达** `HwndTarget.HandleMessage`，但 **`HwndTarget` 已 dispose** ⇒ `WM_GETOBJECT` case 不执行 ⇒ `UiaReturnRawElementProvider` 从不被调用
- **与 L-1 同源**：`HwndTarget` 在无渲染后端（`MilPresent` 缺失）时被提前释放
- **判定为限制**：与 L-1 同一工程量

## L-3 9 个 `role=frame` 的 `name` 为空串

- **现象**：`win_800001` / `win_800003` / `win_800004` / `win_800006` / `win_80000a` 的 `name` 为空
- **证据**：`proof-uia-dumptree.json` 中 5 个 `"name": ""`
- **根因**：这些是 WPF 的内部隐藏窗口（`MediaContextNotificationWindow` 之外，如 HwndWrapper 内部 message-only 窗口），本就没有标题
- **判定为限制**：**不是缺陷**（Windows 上同样为空），无需修

## L-4 仓库标签页（`RepoTabPanel`）未渲染

- **现象**：双击仓库后回到主窗口（截图 8864 字节 = 空白）
- **根因**：与 L-1 同源（无渲染后端 ⇒ 标签页就算创建也不可见）
- **判定为限制**：与 L-1 同一工程量
