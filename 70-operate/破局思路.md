# 破局思路 —— 卡住时的抽象解法

> 这份文件记录的是**跨越具体技术栈的方法论**，不是某一条坑的具体修复。
> 目的：下次遇到形态不同但结构相同的问题时，先照这里走一遍，不要重蹈「把约束当终点」的覆辙。
>
> 来源：2026-10-31 用户在我把四条线都判为「平台硬边界/环境不可行」之后给的指示。
> 我的错误是把「工具链只有 A」「渠道只有 B」「环境只有 C」当成了目标不可达的理由 ——
> 而这三者**都是可替换的**，只有目标本身不可替换。

## 一、四条通用破局路径

### 1. 实现语言不是约束，目标是约束

**错误做法**：发现某组件的真实现是 C++/CLI（`.vcxproj`），而 C++/CLI 只有 MSVC 支持，就判定「Linux 上不可达」。

**正确做法**：问两个问题 ——
- 这段实现**必须**用原语言写吗？→ 不一定。多数情况下可以用 **.NET 托管实现**重写最小可用面。
- 有没有**性能敏感**的部分？→ 有的话用 **GCC 写 C** 并 `DllImport` 进来。

**判据**：先划出「目标实际需要的那一小块 API 面」（不是完整实现），再决定这一小块用什么写。
本次实例 → `System.Printing` 只需要 `LocalPrintServer` 构造 / 拿 `PrintQueue` / `CreateXpsDocumentWriter` / `Write(FixedDocument)` 四步，完全可以用托管重写。

### 2. 获取渠道要穷举，不要单点判死

**错误做法**：`NuGet` 不可达 ⇒ 判定「拿不到诊断工具」。

**正确做法**：把「拿不到」拆成「从哪个渠道拿不到」，然后穷举替代渠道 ——
源码（gitee / 国内镜像）/ 官方 release 直链 / `apt` / 发行版包 / 从源码自己编 / 静态链接进自己的产物。

**判据**：只要**目标产物**能通过**任一**渠道到手，就不算阻塞。
本次实例 → `dotnet-dump`/`dotnet-sos` 可能没有 gitee 镜像，但 `COMPlus_JitDump`/`COMPlus_LogEnable` 这类**环境变量**是运行时自带能力，零成本。

### 3. 环境缺失要换验证方式，不是放弃验证

**错误做法**：本机没有能用的 `ibus` ⇒ 判定「IME 路线不可行」。

**正确做法**：把「验证 X」拆成「验证 X 的哪一部分」，然后对每一部分找**能在当前环境跑**的最小验证 ——
自建（`unshare`/容器）/ mock（自己写一个只实现必需接口的假 daemon）/ 协议层直测（跳过上层直接压字节）/ **只验自己这侧**（把外部依赖桩掉，验证我方代码正确）。
并同时回答：**真实用户场景下这条链到底怎么走**（去查已有项目怎么解，比如 Wine 的 `imm32`）。

**判据**：能验证「我方实现正确」就是有效进展；环境侧的限制单独记录，不算实现缺陷。

### 4. 卡住先问用户，不要替用户决定「到此为止」

**错误做法**：把四条线都标成 blocked，然后自己写交付文档收尾。

**正确做法**：在判 blocked 之前，**先把「我需要什么才能继续」明确列给用户** ——
用户可能持有本机之外的资源、经验、或授权（比如「非 NuGet 渠道允许」「换个实现语言允许」）。

**判据**：每一轮结束前自问一句 ——
> **「我这轮有没有把某个『可替换的东西』当成了『不可替换的目标』？」**

## 二、自查清单（卡住时逐条过）

| # | 自问 | 若答「是」则 |
|---|---|---|
| 1 | 我是不是把「某工具链不可用」当成了「目标不可达」？ | 换实现语言（.NET 重写 / GCC 写 C） |
| 2 | 我是不是把「某渠道不通」当成了「拿不到」？ | 穷举其它渠道（源码/镜像/直链/apt/自编） |
| 3 | 我是不是把「环境缺 X」当成了「不能验证 Y」？ | 换验证方式（自建/mock/协议层直测/只验我方） |
| 4 | 我是不是在替用户决定「到此为止」？ | 先把「需要什么」明确问用户 |
| 5 | 我划的「必须实现的最小面」是不是过大了？ | 只做判据真正断言的那几条 |

## 三、本次实例的映射

| 阻塞项 | 我当时的判定 | 按本文件应走的路径 |
|---|---|---|
| `System.Printing` 是 C++/CLI | 「平台硬边界，SKIP」 | 路径 1：用 .NET 托管重写最小面（4 步 API），性能敏感处 GCC |
| 缺 CoreCLR 诊断工具 | 「本机没有，NuGet 不可达」 | 路径 2：环境变量诊断 / 非 NuGet 渠道 / `gdb` + `libcoreclr.so` 符号 |
| 没有可用 `ibus` 机器 | 「环境缺口，换机器才行」 | 路径 3：自建 bus + mock daemon / 协议层直测 / 只验我方 `wpf_himc` / 查 Wine 怎么解 |
| 四条线全 blocked | 「60 轮用尽，写交付文档」 | 路径 4：先把「需要什么」列给用户 |
