## 七、结论

**本项目在「不引入 wine/mono、只用本仓 shim + 官方 .NET 10 WPF + Cecil patch」的约束下：**

**已达成（可复现、有实测证据）：**
- UIA 枚举 151 控件 / 14 类 / 完整序列
- 七大菜单 name 7/7 + role + 展开截图
- Invoke 真正触发（`INVOKED ok`）
- 提交列表填充 16 提交（37801B / 518 色）
- AT-SPI frame name 9/9
- 真实界面截图 5/10 达标
- shim 可构建可复现（md5 一致）

**未达成（有明确技术障碍）：**
- Add 表单（L-14，7 方案全失败）
- 子窗口 >20000B 截图（L-13，尺寸锁死）
- 多窗口同时渲染（K-1121）
- 工具栏五按钮 / 搜索框 / 状态栏名（控件不存在或无文本）
- AT-SPI Action 端到端（pyatspi 侧未通）

**所有「未达成」都不是「没做」，而是「做了、失败、有具体异常名 + K 号记录」。**

## 八、AT-SPI `Action` 接口的最终状态（T3）

| 能力 | 实测结果 | 记录 |

| **`Accessible.GetName`** | `gdbus` → `('SourceTree',)` | K-1185 |
| **shim 侧 `set_action`** | `[ATSPI-ACT2] set_action OK` | K-1165 |

**未达成（2/7）：**

| 能力 | 实测结果 | 记录 |
|---|---|---|
| **`Action.GetName(0)`** | `UnknownMethod`（`gdbus` 和 `dbus-send` 都失败，诊断显示**请求未到 handler**）| K-1186/K-1187 |
| **`DoAction(0)`** | 未验证（依赖上一条）| — |

**关键发现（对后续有用）：**
- **AT-SPI 的 `NActions` 是**属性**（不是 `GetActions` 方法的长度）** —— K-1182
- **`libatspi` 靠 `GetInterfaces` 判断接口存在** —— K-1179/K-1180
- **`gdbus` / `dbus-send` 可绕过 `libatspi` 直连 shim** —— K-1185
- **`atspi_diag` 用 `WPF_LINUX_KEY_DIAG`**（不是 `WPF_LINUX_ATSPI_DIAG`）—— K-1186
