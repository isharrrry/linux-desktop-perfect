# 需求输入 — 2026-10-30

**来源**：项目发起人（本会话）
**用途**：`20-spec/需求与验收判据文档.md` 的唯一上游；本文件只记录输入，不做设计判断。

---

## 1. 原始目标

把 `dotnet/wpf`（及整个 `Microsoft.WindowsDesktop.App`）的 Windows 专有面替换为 Linux 实现，目标「完美 on Linux」。发起人明确列出的面：

- **WPF**：DWM、UIA、XPS 打印、DRM、DirectWrite 特性、字体回退、输入法、DPI、Aero/Luna/Royale 主题、Ribbon、Media、Ink。
- **WinForms**：COM/ActiveX、设计器、MSAA。

达成路径（发起人设想）：把现有 `WPFOnLinux` 里灌入的原生实现抽成「原生替代仓」，结构调好后补齐其他适配，最后对 `dotnet/wpf`、`dotnet/winforms`、`dotnet/windowsdesktop` 做少量接线改动。

---

## 2. 六项已裁决

| # | 问题 | 裁决 |
|---|---|---|
| 1 | 兼容级别 | **源码级重编**：只保证源码在 Linux 重编后完整运行；不加载 Windows 编译的 dll/exe |
| 2 | 验收口径 | **特性矩阵 + Windows 对照**：每项有 Linux 实测判据 + Windows 基准（帧/行为/API 覆盖），未达标即红 |
| 3 | 首发范围 | **只做 WPF，WinForms 仅兼容层**：不承诺设计器/ActiveX/MSAA 全覆盖 |
| 4 | 不可完美项 | 允许降级/排除：WinForms 设计器、ActiveX/DCOM（只进程内 COM 桩）、IME（接 ibus/fcitx5）、Media（GStreamer）、主题（视觉复刻不映射系统主题）。**DRM 未被勾选**，按规则视为「必须等价」，见开放项 |
| 5 | 仓形态 | **单仓 monorepo**，名 `linux-desktop-perfect`，aidash 式 00–90 阶段目录 |
| 6 | 基线与平台 | **.NET 10 LTS（10.0.x）+ x64/X11 首发**；Wayland、arm64 后置 |

## 4. 开放项（需发起人裁决）

| 编号 | 问题 | 为什么不能自行决定 |
|---|---|---|
| DQ-001 | DRM 处置 | 未勾选降级 ⇒ 按规则「必须等价」；但 MsDrm/PlayReady 无公开规范、无可自建许可服务，等价实现不可行 |
| DQ-002 | `WpfGfx.Linux` 源码缺失 | 迁移与否取决于源码能否找回；找不到则必须重写，工作量与阶段 1 出口条件都变 |
| DQ-003 | WinForms 兼容层「基础控件」边界 | 「基础」未被定义；六控件与全控件的工作量差一个数量级 |
| DQ-004 | 上游同步节奏 | 每个 10.0.x patch 跟随会持续消耗 applier 维护成本；只随初始版会漏安全修复 |
