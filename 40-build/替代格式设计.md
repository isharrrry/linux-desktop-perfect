# 替代格式设计：无法验证的私有格式，怎么在 Linux 侧自洽

> **问题**：有几个 Windows 私有格式，本仓既没有样本可验证、也没有公开规范。
> 之前的做法是「返回 E_NOTIMPL」——**那是把功能关死，不是让它能用**。
> 本文档给出**替代格式**的设计：**在 Linux 侧自洽即可，不要求与 Windows 互认**。
>
> **适用范围**：`InkCanvas` 墨迹序列化、打印的 DEVMODE/PrintTicket。
> **不适用**：BSTR / HSTRING / MMCKINFO —— 那些是**公开规范**，已按原格式实现（K-199/201）。

## 判据：什么时候可以用替代格式

**用**：该格式只在**本进程/本机内**流转（写出去、读回来，中间不经过 Windows）。
**不用**：格式要传给 Windows 程序，或 Windows 程序写的数据要我们读。

本仓的墨迹与打印都属于**前者**：`InkCanvas` 存 `.isf` 只给自己下次读；打印队列是本机 CUPS。
⇒ **替代格式合法，且是唯一能让功能"能用"的路。**

## 一、ISF（Ink Serialized Format）压缩

### 现状
`MOD-84` 的 5 个 `Isf*` 符号（`IsfLoadCompressor` / `IsfCompressPacketData` /
`IsfCompressPropertyData` / `IsfDecompressPacketData` / `IsfDecompressPropertyData`）
现在是安全桩（返回 0）。后果：**`InkCanvas` 的墨迹保存/加载不可用**。

### 原格式为什么不可验证
ISF 的压缩段用的是微软私有的 **ISF 压缩算法**（不是 zlib/deflate，是自研的字典压缩），
**没有公开规范**，本仓也没有 `.isf` 样本可比对 ⇒ 写完无法判断对错。

### 替代设计（**推荐**）
**保留 ISF 的外层容器结构，压缩段换成 zlib**（我们已经有 `libSystem.IO.Compression.Native.so` 的适配层）：

```
[ISF 头 8 字节: 'ISF\0' + 版本]
[段类型 4 字节: 0x00000001 = 未压缩, 0x00000002 = zlib（替代格式的标记）]
[段长度 4 字节]
[段数据: deflate 流]
```

- **写**：段类型写 `0x00000002`（zlib），数据用 `CompressionNative_Deflate`
- **读**：按段类型分派 —— `0x00000002` 用 `CompressionNative_Inflate`；
  `0x00000001` 直接拷贝（兼容未压缩的旧文件）
- **遇到 `0x00000002` 之外的未知类型** ⇒ 返回明确错误码，**不猜**

### 自洽性保证
写出去的文件**只有我们自己读**（`.isf` 存在用户目录），所以不需要和 Windows 互认。
**唯一要求**：同一台机器上「存 → 读」往返后，墨迹点数据逐字节相同。可以写一个往返用例验证。

### 登记
替代格式的标记值 `0x00000002` 必须写进 `70-operate/已知坑清单.md`，
并在文件头注释里写明「本仓产出的 `.isf` **不保证 Windows 可读**」。

## 二、DEVMODE / PrintTicket（打印）

### 现状
`MOD-82` 的 7 个 `PT*` 符号返回 `E_NOTIMPL`。后果：**打印机的"首选项"对话框与
PrintTicket 校验不可用**（但打印本身走 CUPS，ACC-024 已 PASS）。

### 原格式为什么不可验证
`DEVMODE` 是 **200+ 字节、按驱动变化的二进制结构**（每个打印机驱动可以追加私有字段）；
`PrintTicket` 是一套带 XSD 的 XML，命名空间和元素由打印架构定义。
**两者都不能靠"猜布局"实现。**

### 替代设计
**不做 DEVMODE/PrintTicket 的二进制互认**，改为**把"打印设置"抽象成一组键值对**：

```c
typedef struct {
    char  key[64];      /* "PageSize" / "Orientation" / "Color" / "Duplex" ... */
    char  value[128];   /* "A4" / "Portrait" / "Color" / "Simplex" */
} wpf_print_option;
```

- `PTGetPrintCapabilities` → 从 **CUPS 的 PPD 文件**（`/etc/cups/ppd/<queue>.ppd`）
  读出可选项，转成上面的键值对数组
- `PTConvertDevModeToPrintTicket` / `PTConvertPrintTicketToDevMode` → 键值对 ↔ 我们自定义的
  `DEVMODE` 副本（**只在内存里流转，不落盘**）
- `PTMergeAndValidatePrintTicket` → 键值对的合并与取值合法性检查（A4/Letter/…）

### 自洽性保证
CUPS 的 PPD **是公开的文本格式**，可以真读 ⇒ 这一步是**真实现**，不是替代。
替代的只是「DEVMODE 二进制 ↔ PrintTicket XML」这一层，而它**只在我们的进程内流转**。

### 登记
在 `缺口影响对照表.md` 里把 `PT*` 从「E_NOTIMPL」改为「替代格式：PPD 键值对」，
并注明**「不保证 Windows 生成的 PrintTicket 能被本仓解析」**。

## 三、手写识别（`mshwgst` 14 个）—— **没有替代格式**

`CreateRecognizer` / `AddStroke` / `GetAlternateList` / `GetLatticePtr` 等是**识别引擎本身**，
不是格式问题。Linux 上有可用的开源方案（如 `MyScript` 商业、`zinnia`/`tegaki` 开源），
但**接引擎是一项独立工程**，不是"换个格式"能解决的。

⇒ **保持安全桩（返回 0）**，并在对照表里写明：
「**手写识别不可用；墨迹采集与显示不受影响**」。
如果将来要接，建议接 `zinnia`（C++，可静态链），入口就在 `CreateRecognizer` + `AddStroke` + `GetAlternateList`。

## 四、优先级与工作量

| 项 | 价值 | 工作量 | 建议 |
|---|---|---|---|
| **ISF zlib 替代** | 让 `InkCanvas` 能存/读墨迹 | ~120 行 C（复用已有 zlib 适配层）| **先做** |
| **打印 PPD 键值对** | 打印首选项可读 | ~200 行 C（PPD 解析）| 次做 |
| **手写识别接 zinnia** | 手写转文字 | 独立工程（需引入第三方库）| 不在此目标范围 |

## 五、这条设计的原则

1. **能公开的按公开规范做**（BSTR/HSTRING/MMCKINFO 已按原格式实现）
2. **私有且只在本地流转的，用替代格式，并明确标记"不互认"**
3. **引擎类（识别/解码）不硬造** —— 返回明确错误码，让调用方走回退
4. **每个替代格式都必须有往返用例**（存→读→逐字节相同），否则不算完成
