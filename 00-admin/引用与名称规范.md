# 引用与名称规范

> 本文件是 LinuxDesktopPerfect 全仓的**引用规则唯一事实源**。写作、评审、验收、Agent 改文档一律照此执行。
> 与 [《术语表》](术语表.md) 的分工：术语表管「叫什么」，本文件管「怎么引、怎么链、怎么校验」。

---

## 1. 两种引用标记：能读的用《》，不能读的用 #

判据只有一条：**这份东西人能不能直接读。**

| 类型 | 标记 | 写成链接 | 示例 |
|---|---|---|---|
| 可阅读文档：设计说明、需求、报告、模板、README | **《文档名》** | 是，链到文件 | [《概要设计》](../30-design/概要设计.md)、[《需求与验收判据文档》](../20-spec/需求与验收判据文档.md) |
| 不可阅读：脚本、数据、配置、Schema、清单 | **#工具名** | 是，链到文件 | [#名称清单](../30-design/model/names.json)、#链接检查器 |
| 网页 | 中文名，不加标记 | 是 | 无（本仓暂无） |
| 目录 | **#目录名** | 是，链到目录 | #native-shim 目录 |

**规则**：

1. 文档名取文件名去掉 `.md`，保留编号前缀（《需求与验收判据文档》《概要设计》）。
2. 章节号写在标记**之后**，不塞进括号：[《概要设计》](../30-design/概要设计.md) §5。
3. 同一页面/工具在全仓用同一个名字；名称以 [《术语表》](术语表.md) 为准。
4. **代码块与命令行里的文件名保留原样**——那是要照着敲的，不能换成标记。
5. **行内代码包裹的路径**（如 `` `40-build/native-shim/` ``）只作位置说明，不算引用；若它指向本仓一份可阅读文档，必须同时给出《》链接，否则视为违规。

---

## 2. 路径与链接

- 路径**相对于当前文件所在目录**；跨目录用 `../`。
- **一律正斜杠**。反斜杠、绝对路径、`file://`、`<...>` 包裹路径一律禁止。
- 仓库外文件（同机兄弟仓、临时件）**不写 Markdown 链接**：用行内代码给机器路径，并说明「它是什么、用来判定什么」。
- 派生件与原文摘录**不改名**：`10-input/` 下的原始记录保持原样；`90-archive/` 只读。
- 提到别的文档或工具，一律写成链接；**可解析的裸路径一律算违规**（判据：该路径在本仓存在且以 `.md` 结尾，却没有用链接包裹）。

---

## 3. 引用定位：写章节／编号／简述，不写裸行号

**约束**：本仓文档之间相互引用，**不得只写行号**（`L` 加数字）。行号会随改版漂移，读者无法复核。必须落到以下三种之一：

| 写法 | 形式 | 例 |
|---|---|---|
| 章节号 | `§` + 多级编号 | [《概要设计》](../30-design/概要设计.md) §5、§4.6 |
| 关键编号 | 文档内稳定标识 | ADR-001、MOD-31、REQ-FN-015、ACC-013、DQ-002 |
| 内容简述 | 引号括起，≤10 字 | 「三条契约」「六控件」 |

**允许的组合**：章节号 + 短语（§5「12 项专有面」）、编号 + 章节（MOD-31（§4.5））。

**唯一例外——上游源码证据**：引用本仓之外的源码位置时，允许 `文件名:行号`，但必须同时给文件名与「上游」限定，例如「上游 `src/Microsoft.DotNet.Wpf/src/Shared/RefAssemblyAttrs.cs:67-80`」。本仓文档之间的引用不适用此例外。

**自检**：`grep -nE '\bL[0-9]{2,}\b' <文件>` 应无输出（代码块豁免）。

## 4. 四张表示的分工与权威

同一套系统在本仓有四类平行表示。它们回答不同问题，**不互相「对齐」**；只对齐「每条信息归谁管」。

| 表示 | 回答什么 | 权威在哪 | 不归它管 |
|---|---|---|---|
| **名称口径** | 这个东西叫什么、不叫什么 | [《术语表》](术语表.md) + [#名称清单](../30-design/model/names.json) | 字段、介质、行为 |
| **需求编号** | 要什么、怎么验收 | [《需求与验收判据文档》](../20-spec/需求与验收判据文档.md)（REQ/ACC/NF/XIF/DQ） | 实现细节 |
| **设计编号** | 怎么建、边界在哪 | [《概要设计》](../30-design/概要设计.md)（ADR/MOD/SYS/R） | 字段级契约（→ 04）、表结构（→ 05） |
| **契约文件** | 原生层边界长什么样 | `exports.txt`、`win32_abi.h`、DUCE 布局表、`FrameworkList` | 业务语义 |

**四条纪律**：

1. **接口的一切以 04-IDD 为准**（设计包补齐后）；概设只给接口概览，不定义字段。
2. **上游证据不可改**：引用上游文件时保留原始路径；改了就失去证据意义。
3. **编号只在定义方定义**：REQ/ACC 在 `20-spec`，ADR/MOD/R 在 `30-design/概要设计.md`；其他文件只引用。
4. **名称只在术语表定义**：正文出现异名即视为待改；`names.json` 是给脚本读的机器版，冲突时改机器版对齐术语表。

## 6. 校验（改完必须跑）

```bash
node 30-design/checks/check-links.mjs     # 标记合规 + 路径可解析 + 裸路径/裸行号
node 30-design/checks/check-package.mjs   # 文档头 + 编号引用 + 覆盖矩阵
node 30-design/checks/selftest.mjs        # 改规则/改检查器后必跑：负向断言
```

两条都必须 `rc=0` 才算文档改动完成。检查项：

| 脚本 | 检查什么 |
|---|---|
| #链接检查器 | 相对路径可解析；禁绝对路径/反斜杠/file:///尖括号；《》/# 标记；裸 `.md` 路径；裸 `L####` |
| #文档包检查器 | 必备文件与文档头；REQ/ACC/ADR/MOD/DQ 引用不悬空；REQ→ACC→MOD 覆盖；术语首选名 |

**豁免**：代码块内、行内代码内、`90-archive/` 下的归档文件不参与检查。

---

## 7. 给 Agent 的硬约束

1. 改文档前先读 [《术语表》](术语表.md) 与 [《引用与名称规范》](引用与名称规范.md)（本文件）。
2. 新增或改写引用，必须用《》/# 标记 + 相对链接；不得新增裸路径、裸行号。
3. 改完全部 `.md` 后跑 §6 两条命令，`rc=0` 才算完成。
4. 不得改 `90-archive/`；不得改 `10-input/` 的原始记录（只追加新文件）。
5. 编号只在定义方定义；引用已有编号，不新造。
6. 名称一律用 [《术语表》](术语表.md) 的首选名；发现异名，先改文档再改 `names.json`。
